# بيئات الدفع والتجربة والنشر

تحديث: 18 أكتوبر 2026. ينطبق على لحظة وجوال باي.

## اختيار البيئة تلقائيًا

`PaymentEnvironment` يقرأ بيئة .NET:

- `Development`: Sandbox. سكربت `scripts/start-local.ps1` يشغّل Web وWorker بهذه البيئة حتى عندما يكون البناء Release.
- الأسماء الأخرى مثل `Staging` تبقى Sandbox احتياطًا، لكن أمثلة الهاتف والرمز لا تظهر للعامة إلا في Development.
- `Production`: بيئة الدفع الحقيقية، وهي الافتراضية عند النشر إذا لم يُفرض اسم بيئة آخر. على الاستضافة اضبط Web وWorker على Production؛ لا تنقل إعداد تشغيل Development إلى خدمة الإنتاج.

لا يحدد الزائر البيئة ولا يرسلها في form، ولا يعتمد الاختيار على وجود ngrok أو اسم الدومين أو كون البناء Debug/Release. تبقى الإعدادات بالطريقة التقليدية داخل `appsettings.json` في المشروعين، دون user-secrets.

## الإعدادات التي تستبدلها أنت أخيرًا

في Web وWorker، القيم نفسها للمشروعين:

```text
Payments:JawwalPay:Sandbox:ApiKey       مفتاح الاختبار من الشريك
Payments:JawwalPay:Production:ApiKey    مفتاح الإنتاج عند النشر
Payments:Lahza:Sandbox:SecretKey       مفتاح لحظة sk_test_
Payments:Lahza:Production:SecretKey    مفتاح لحظة sk_live_
Payments:Lahza:Sandbox:PublicOrigin    رابط ngrok الحالي
Payments:Lahza:Production:PublicOrigin أصل الموقع HTTPS عند النشر
```

إذا أكد الشريك أن مفتاح جوال باي نفسه صالح للمسارين، يمكن وضعه في القسمين؛ لا يغيّر ذلك مسارات Sandbox/Production التي يختارها السيرفر. مفتاح لحظة مختلف حسب الوضع. القيم السرية الافتراضية `***` تمنع الجاهزية، ولا تُرفع مفاتيح حقيقية إلى GitHub أو تُرسل في المحادثة.

القيم الثابتة من عقد جوال باي مضبوطة، ومنها `ApiKeyHeader=X-Partner-Key`. لا يحتاج المستخدم إدخال المفتاح ولا يرى `session_key`؛ المتصفح يرسل الهاتف وOTP إلى موقعنا فقط.

## جوال باي في Sandbox

| العملية | الطريقة والمسار |
| --- | --- |
| فحص المفتاح | `GET /api/partner/test/ping` |
| بدء جلسة تجريبية | `POST /api/partner/test/pay/initiate` |
| تأكيد تجريبي | `POST /api/partner/test/pay/confirm` |

الأصل `https://store.portal.ps`. وفق معلومات المزود: **لا خصم ولا SMS** لهذه المسارات.

- رقم التجربة: `0599123456`.
- رمز النجاح: `123456`.
- صفحة الدفع في Development تعرض ملاحظة Sandbox؛ يظهر الرقم في خطوة الهاتف، والرمز بجانب حقل OTP وكـplaceholder في خطوته. لا يجري تأكيد تلقائي.
- في Production لا تظهر الملاحظة أو الرقم التجريبي أو رمز النجاح، ولا تُملأ حقول الإنتاج بهذه الأمثلة.
- لم يُزوّدنا المزود بمسار Sandbox للرصيد أو قائمة العمليات؛ لذلك لا يستدعي Sandbox مسارات الإنتاج لهذه الأغراض. إذا انقطع رد التأكيد قبل حفظ الإيصال، يبقى الطلب غير محسوم ولا يعاد confirm؛ يمكن اختبار جلسة جديدة أو طلب مراجعة. إذا حفظ الإيصال قبل تعطل اعتماد الاشتراك، يستكمل العامل من الإيصال المحفوظ.
- التنفيذ يتوقع حقول رد initiate/confirm الموثقة لعقد الشريك نفسه. إذا كانت ردود Sandbox مختلفة، احتفظ بالتشخيص المحجوب وأرسل الحقول دون مفتاح أو OTP حي لاستكمال المطابقة؛ لا يعتمد النظام نجاحًا غير موثّق.

## الأدوات والفحوص

أضيفت بطاقتا لحظة وجوال باي إلى الأدوات. تعملان ضمن «فحص الأدوات الآن» أو الفحص اليومي منتصف الليل بتوقيت فلسطين، دون إضافة فحص عند كل زيارة أو تحديث نتائج.

| البوابة والبيئة | الفحص |
| --- | --- |
| لحظة Sandbox/Production | `GET /payment_session_timeout` بمفتاح البيئة المختارة، دون تعديل المهلة |
| جوال باي Sandbox | `GET /api/partner/test/ping` |
| جوال باي Production | `GET /api/partner/balance` |

كلها للقراءة فقط: لا initialize أو initiate أو confirm، ولا خصم أو إرسال رمز. تعرض البطاقة بيئة الفحص ووقته ومدته وحالته، ولا تعرض المفتاح أو جسم الرد. نجاح الفحص يثبت قبول الاستعلام، وليس جودة الدفع أو نجاح عملية معينة. فحص ping يشترط رد JSON ناجحًا بعلامة `ok=true`؛ الرد غير المعروف لا يظهر نجاحًا أخضر.

تستطيع الإدارة جلب رصيد جوال باي الحقيقي يدويًا من «بوابات الدفع ← إعداد جوال باي». زر الرصيد معطل في Sandbox لعدم وجود مسار تجريبي موثق. قائمة العمليات المحلية تتصفح 10 سجلات في كل صفحة.

## عزل الطلبات والاشتراكات

يُحفظ `GatewayEnvironment` على الطلب وعلى فترة الاشتراك. لا تُعالج جلسة أو طلب في بيئة أخرى، ولا تتصل Webhooks لحظة بمفتاح البيئة الأخرى. استعلامات صلاحيات الاشتراك وتجديده وتنبيهاته تقرأ فترات البيئة الحالية فقط؛ اشتراك Sandbox لا يفتح مزايا Production حتى لو كانت القاعدة مشتركة.

السجلات الموجودة قبل إضافة العزل تُصنّف Production حفاظًا على البيانات السابقة؛ إذا كانت لديك دفعات اختبار قديمة قبل هذه الإضافة، راجعها قبل النشر ولا تعتبرها حقيقية تلقائيًا. لا يحوّل التطبيق بياناتك القديمة أو يحذفها تخمينًا.

استخدم **قاعدة بيانات مستقلة للتطوير والإنتاج**، ويفضل بوتًا مستقلًا أيضًا. عزل الاشتراكات لا يعزل حسابات Identity وأكواد التحقق ومنشورات الجمع وكل البيانات المشتركة. لا تشغّل عاملي تطوير وإنتاج على قاعدة مشتركة؛ راجع طابور رسائل الاختبار قبل النشر.

## التسلسل المحلي

1. طبّق الكود الجديد على قاعدة تجربة مع نسخة احتياطية. Web يطبق migrations عند البدء وفق آلية المشروع الحالية.
2. ضع مفاتيح Sandbox أخيرًا في ملفي الإعدادات؛ أبقِ Production `***` أثناء التجربة. أكمل إعداد تليجرام للتسجيل إن لم يكن مفعلًا.
3. أعد تشغيل `scripts/stop-local.ps1` ثم `scripts/start-local.ps1`، وشغّل ngrok إذا كنت تجرب تليجرام أو عودة/Webhook لحظة. جوال باي نفسها تتصل من السيرفر ولا تحتاج نفقًا من هذه المسارات.
4. من الأدوات اطلب الفحص وانتظر العامل ثم حدّث النتائج؛ تحقق أن بطاقتي الدفع تعرضان Sandbox.
5. من بوابات الدفع فعّل البوابة بعد جاهزية مفتاحها. أنشئ باقة أو اختر القائمة، ثم ادخل بعضو مفعل واشترِ باستخدام بيانات Sandbox أعلاه.
6. جرّب رفض الرمز وإعادة الضغط وانتهاء المهلة. لا يعاد confirm لنفس الجلسة حتى لو أخطأت في الرمز؛ هذه تعليمات الشريك. لا تفسر تحديث الصفحة على أنه محاولة دفع جديدة.

## من النشر إلى التشغيل

1. انشر Web وWorker كاملين وفق دليل النشر، واختر Production للعمليتين.
2. ضع مفاتيح Production في مخرجات النشر، واضبط أصل الموقع الحقيقي في `Seo:PublicOrigin` و`Payments:Lahza:Production:PublicOrigin` في المشروعين. لا تستخدم أصل ngrok للإنتاج.
3. احفظ مفاتيح Data Protection ومجلد بيانات Web الدائم: جلسة جوال باي مشفرة بهذه المفاتيح حتى بدء التأكيد. تغيير/فقدان المفاتيح قد يمنع إكمال جلسة لم تبدأ تأكيدها.
4. طبّق migrations قبل تشغيل العامل. احتفظ بنسخة SQL احتياطية؛ Down محمي من إزالة تاريخ جلسات المحفظة أو تاريخ Sandbox.
5. حدّث Webhooks تليجرام ولحظة إلى HTTPS الحقيقي. اربط Webhook لحظة Live بمفتاح Live.
6. شغّل فحص الأدوات للقراءة فقط وتأكد من Production. افتح صفحة العضو وتأكد من اختفاء بيانات التجربة. جرّب معاملة إنتاج محددة لاحقًا بعد مراجعة المبلغ والحساب؛ لم تنفذ البيئة السحابية أي خصم أو إرسال فعلي.

## نتائج التحقق في البيئة السحابية

- نجح بناء الحل ومشروع الفحوص. التحذيرات الموجودة لحزمة System.Security.Cryptography.Pkcs 9.0.11 بقيت كما كانت؛ لم تُرقّ الحزم ضمن هذه المهمة.
- نجح 55 فحص عقد جوال باي وSandbox والأدوات، و34 فحص لحظة، و103 فحوص عضوية وحقن البيئة ومسارات HTTP، و14 فحص ترقيم: 206 إجمالًا.
- نجح عرض Chromium في 24 حالة: شاشتا الهاتف والرمز، الأدوات والإعداد، بالعربية والإنجليزية، في Development وProduction، بعرضي الهاتف وسطح المكتب للشاشات المالية، دون خروج أفقي. تأكد ظهور رقم التجربة/الرمز في Development واختفائهما في Production.
- تولّد SQL لتحديث المخطط وتطابق model وsnapshot. لم يطبق على SQL حي. اختبارات SQL المتزامنة جاهزة ضمن --membership-sql-check لكنها لم تُشغّل لعدم توفر اتصال اختبار.
- كل اتصالات الفحوص المالية كانت HTTP محاكى. لم يُستخدم مفتاح حقيقي، ولم يرسل فحص الأدوات OTP أو ينشئ خصمًا. سكربت PowerShell يحتاج تشغيله على جهاز المستخدم؛ لم يُجرّب على Windows هنا.
