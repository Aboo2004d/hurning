# متابعة تنظيف الكود

## الدفعة الحالية

إعادة تنظيم للمسارات القائمة، مع بقاء إعدادات المزودين وقاعدة البيانات ومسارات HTTP كما هي. لا تضيف هذه الدفعة ميزة نشر أو عملية دفع جديدة.

| المجال | الخدمة أو القاعدة | الحد مع الواجهة |
| --- | --- | --- |
| رسائل التواصل | `ContactInboxService` | ملخصات للقائمة وتفاصيل منفصلة؛ تبقى القراءة عند فتح الرسالة وتغيير المعالجة محفوظتين في الخدمة |
| البلاغات | `ReportManagementService` | `UserReportSummaryDto` بدل تحميل كيان الفرصة كاملًا |
| سجل الدمج | `MergeAdministrationService` | ملخص بلا لقطات الاستعادة؛ التراجع يفوض معاملة `MergeHistory` الحالية |
| إشعارات العضو وصندوق البوت | `NotificationAdministrationService` | DTOs بلا payload أو معرفات النقل؛ طلب إعادة المحاولة لا يرسل من Controller |
| لوحة الإدارة وطابور الجمع | `AdminDashboardReadService` و`SourceItemAdministrationService` | عدادات وملخصات منفصلة؛ تفاصيل العنصر لا ترجع Source أو إعداداته |
| استهلاك AI | `AiUsageReadService` | إسقاط للطلبات وتجميع يحتفظ بالفرق بين العدد المفقود والصفر |
| محرر تعليمات AI | `PromptAdministrationService` و`PromptInputRules` | DTOs للإعدادات والتاريخ والأمر؛ النسخة الجديدة والمؤشر المعلق داخل معاملة واحدة |
| الاحتفاظ بالبيانات | `RetentionSettingsService` | قراءة وتعديل سياسة فقط؛ لا ينفذ طلب الويب حذف البيانات |
| صفحات المحتوى والأسئلة | `SiteContentService` و`SiteQuestionsDraft` | DTOs للقراءة وأوامر حفظ بإصدار؛ أوامر ترتيب المسودة لا تحفظ |
| ملفات التشخيص | `CollectorDiagnosticReadService` | يبقى وجود سجل التدقيق شرطًا قبل قراءة الملف أو إرجاع مسار الصورة |
| أدلة تواريخ العنصر | `SourceItemEvidencePresenter` | تحليل JSON وإيجاد صفحة الدليل خارج Razor؛ تعرض الواجهة قيمًا مجهزة |
| تطبيق الاستخراج | `ExtractionCandidateRules` | تجهيز المرشح وأخطاء أدلته منفصل عن المطابقة والحفظ داخل المعاملة |

خدمات الإدارة الجديدة مسجلة scoped عبر `AddAdministrationFeatures`. تنسيق HTTP والتفويض والتحقق من ModelState ورسائل الواجهة تبقى في Controllers. يقبل `AdminPagination` الاستعلام بعد إسقاط DTO مع الحفاظ على الترتيب الذي تحدده خدمة القراءة قبل الترقيم.

لم تتغير قيم الحالات المخزنة أو DTOs المزودين أو جداول قاعدة البيانات. `RecordUpdateOutcome` نتيجة تطبيقية غير مخزنة، ولا تصف نجاح دفع أو نشر.

## قراءة الزائر ومساحة العضو

فُصلت بطاقات الفرص عن تفاصيلها إلى `OpportunityCardDto` و`OpportunityDetailsDto`. أسماء المصادر وروابطها وأدلة التواريخ DTOs مستقلة؛ لا تصل إعدادات المصدر أو ملاحظات المراجعة الداخلية إلى نماذج الزائر. بقي ترتيب تحويل الرابط الدائم ثم فحص استحقاق التفاصيل كما كان.

`PublicListingReadService` يجمع البحث والفلاتر والترتيب والترقيم والقسم المستقل للإغلاق وRSS. `PublicOpportunityScope` يثبت نطاق الحالي والأرشيف والتفاصيل العامة. `PublicSitemapReadService` يقرأ بيانات خرائط الموقع دون XML، بينما يبقى إنشاء الاستجابة في Controller. بيانات SEO والكروت والشارات والمشاركة تحتفظ بسلوكها.

`SavedOpportunityService` يفرض ملكية العضو عند القراءة والإضافة والحذف، ويتحمل سباق الحفظ بالمفتاح الفريد السابق. تميز واجهاته بين معرّف الفرصة ومعرّف صف الحفظ. `MemberAccountReadService` يعيد حالة الحساب دون معرفات تليجرام. `MemberPreferenceService` يحفظ خيارات التنبيه وصيغة JSON نفسها؛ `MemberPreferencePageService` يطبق أوامر المحرر والتحقق من الكتالوج، بما فيه إبقاء القيم القديمة قابلة للإزالة.

`MemberNotificationSettingsService` يملك حفظ إيقاف التنبيهات واستهلاك تفويض تغيير تليجرام. يبقى التحقق من الكوكيز وصلاحية الجلسة والتنقل في الويب. `GoogleLinkViewComponent` و`GoogleLinkReadService` يمنعان وجود استعلامات Identity داخل Razor. استعلاما ملكية مفتاح الشراء ومعاينته أصبحا في `PaymentReadService` دون تغيير شروط البيئة أو تكرار عملية الدفع.

## التحقق التنفيذي

أذن المستخدم لاحقًا بالبناء والاختبار قبل الرفع. بُني الحل ومشروع الفحوص، وأضيفت فحوص لترجمة استعلامات DTO إلى SQL دون فتح اتصال، وتوافق نموذج EF مع migration، وSEO وRSS وتسجيل DI. شُغلت أيضًا حزم المزوّدات الوهمية وفحوص أدوات PDF/OCR والمتصفح المحلي. تفاصيل النتائج والقيود في [تقرير التحقق](QUALITY-VALIDATION.md).

كشف البناء نقص `ContentFingerprint` و`ContentRetryableException` في الدمج السابق؛ استُعيدا من تحديث المستخدم الأصلي في ملفين منفصلين. حُدّثت حزمة `System.Security.Cryptography.Pkcs` إلى `10.0.13` لمعالجة تحذيرات الحزمة غير المباشرة. لم تتغير إعدادات الربط أو migrations أو بيانات المستخدم.

هذه مراجعة للحدود والمسارات المشمولة وليست ادعاءً بأن كل تحسين مستقبلي للجودة انتهى. بعض منسقات تسجيل الدخول والتكاملات تبقى مسؤولة عن تسلسل HTTP والهوية والكوكيز؛ لا تُجزّأ لمجرد تقليل طول الملف. أُبقيت بعض constructors المتوافقة للمستدعين المباشرين، بينما تستخدم خدمات التطبيق المسجلة scoped في التشغيل المعتاد.

## التتبع وقوالب التليجرام وإصلاح الأدوات

نُفذت الميزات بعد إذن المستخدم: سجل العمليات في `/ar/Admin/Operations`، وقوالب مستقلة للقنوات (`Telegram`) وتنبيهات البوت (`TelegramBot`) ضمن محرر القوالب نفسه. التفاصيل وحدود التسجيل والفحوص في [دليل التتبع والتليجرام](OPERATION-TRACKING.md).

يقرأ سجل العمليات من جدول التدقيق الموجود، ويضيف `OperationTracking` أحداث الانتقالات المهمة داخل حفظ الحالة نفسه. لا يسجل نبضات الحياة أو الحمولات الخاصة. أضيف migration لفهرس `Audit(At, Id)` فقط؛ يبقى التاريخ UTC ويعرض بتوقيت فلسطين.

أصبح فحص حداثة كل أداة يستخدم نبضة العامل الذي نفذ نتيجتها، بدل آخر عامل أرسل نبضة حياة. لا يغير فحص أداة واحدة حالة نتائج الأدوات الأخرى المنفذة على عامل آخر ما زال حيًا.
