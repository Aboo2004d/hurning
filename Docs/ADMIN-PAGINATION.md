# تقسيم جداول الإدارة إلى صفحات

كل جدول في لوحة الإدارة يعرض 10 سجلات كحد أقصى. يظهر السابق/التالي عندما يتجاوز عدد النتائج 10 سجلات. كل رابط يرسل GET جديدًا إلى إجراء الصفحة نفسه، ويُنفّذ الترتيب والفلاتر ثم `Skip` و`Take(10)` في SQL قبل تحميل الصفوف. لا تُحمَّل بقية السجلات إلى المتصفح لإخفائها محليًا.

يشمل ذلك الفرص والمراجعة والمصادر والبلاغات ورسائل التواصل وسجل الدمج وسجل نسخ البرومبت وطلبات فحص الأدوات وجدولي المتابعة وجدولي إحصاءات AI. جدول طلبات الشبكة في تفاصيل التشخيص يُقسم أيضًا إلى 10؛ مصدره ملف لقطة تشخيص موجود وليس جدول SQL، لذلك يقرأ الموقع اللقطة ثم يعرض الجزء المطلوب فقط.

الآلية المشتركة موجودة في `Models/AdminPagination.cs` و`Views/Shared/_AdminPagination.cshtml`. تتحقق من رقم الصفحة وتعيده إلى الحدود الصحيحة عند فراغ الجدول أو طلب رقم خارج النطاق. يجب تمرير استعلام مرتب ترتيبًا ثابتًا، مع مفتاح فريد لكسر التعادل.

تحافظ روابط الترقيم على الفلاتر ومعرف النسخة المستعرضة ومسار استضافة التطبيق وأرقام صفحات الجداول الأخرى. في الرئيسية يستخدم جدول الجولات `runsPage` والانتظار `itemsPage`. في إحصاءات AI تستخدم الطلبات `page` والمجاميع `groupsPage`؛ تحسب المجاميع من جميع الطلبات المطابقة لفترة الأيام ثم تقسم صفوف المجاميع، ولا تجمع عشر طلبات فقط. سجل البرومبت يستخدم `historyPage`. تغيير فلتر الأيام أو حالة الرسالة يبدأ من الصفحة الأولى بالطريقة المعتادة للنماذج.

للتحقق دون اتصال بقاعدة بيانات:

```powershell
dotnet run --project tests/HiringPs.Checks -c Release -- --admin-pagination-check
```

الفحوص تشمل حدود الصفحات، آخر صفحة، حفظ الفلاتر والترقيم المستقل، وترجمة الاستعلامات إلى SQL Server مع OFFSET/FETCH NEXT. اختبار التنقل الفعلي مع بيانات SQL Server محلية أو على الاستضافة يحتاج تشغيل الموقع وقاعدة بياناته. لا توجد مهاجرة خاصة بتقسيم الصفحات.
