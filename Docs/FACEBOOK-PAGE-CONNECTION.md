# ربط صفحة Facebook

يبدأ الربط من الإدارة ← التكاملات، بمعرّف الصفحة المحدد. يبقى مسار OAuth كما هو:
`/integrations/facebook/callback` دون بادئة اللغة.

إذا أعاد `me/accounts` قائمة لا تتضمن الصفحة، يطلب النظام الصفحة المحددة مباشرةً بحقول `id,name,access_token` باستخدام رمز المستخدم. لا يقبل مجرد قراءة اسم صفحة عامة: يجب أن يحصل على رمز الصفحة، وأن يعيد `/me` بهذا الرمز المعرّف نفسه، وأن يؤكد `debug_token` صلاحية رمز PAGE للتطبيق المضبوط وصلاحية `pages_manage_posts`. يرفض رمزًا منتهيًا أو إذنًا تفصيليًا يستهدف صفحة مختلفة. يحفظ الرمز مشفرًا بآلية الربط الحالية دون نشر منشور تجريبي.

عند الفشل تظهر رسالة السبب المعروفة، ويسجل `SocialConnection` مرحلة الطلب وحالة HTTP أو رمز السبب ونوع الاستثناء ورقم المتابعة. لا يسجل نص الاستثناء أو محتوى الرد أو query string أو أي رمز وصول. موصل SocialProviders يعطل تسجيل HttpClient لأن طلب debug_token يحتوي الرمز في query string.

للتشخيص محليًا:
```powershell
Get-Content .\artifacts\local-logs\web.out.log -Tail 300 | Select-String 'SocialConnection' -Context 0,2
```

فحوص الموصل:
```text
dotnet run --project tests/HiringPs.Checks -c Release -- --facebook-page-check
```
تستخدم ردود HTTP محاكاة، ولا تتصل بفيسبوك أو SQL ولا تنشر أي محتوى. تشمل غياب الصفحة عن القائمة، واختلاف هوية الصفحة أو التطبيق أو نوع الرمز أو نطاقه، وغياب إذن النشر وانتهاء الصلاحية. يجب إكمال تجربة الربط الفعلية من لوحة الإدارة بعد تحديث النسخة.
