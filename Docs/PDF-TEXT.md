# خطة مؤجلة: تحسين قراءة PDF العربي وOCR

الحالة: مؤجلة بطلب المستخدم. هذا الملف يوثّق مقترحًا لمرحلة لاحقة، وليس سلوكًا
منفذًا أو متطلبات جديدة للإصدار الحالي. لم تُضمّن تعديلات PDF البرمجية في هذه الدفعة.
تبقى قراءة PDF والتحقق وإعادة المحاولة وفق الكود الحالي؛ لا تثبّت أدوات إضافية لهذا الإصدار.

## المشكلة المرصودة

في عطاء الهلال الأحمر `23-ADM HQ-2026` ظهر النص العربي معكوسًا وملتصقًا بعد
استخراجه من PDF النصي. تعثرت مطابقة العنوان والجهة والمكان، وأخطأ النموذج في
بعض الكلمات. استُخرج الموعد `2026-08-16` بشكل صحيح، لكن دليل المصدر احتوى
`ميدقتل16/08/2026`؛ حدّ الكلمة في فحص التاريخ منع اكتشاف التاريخ الملتصق.
الرابط المرجعي:
https://www.palestinercs.org/public/files/image/2026/tenders/23-ADM%20HQ-2026.pdf

## نطاق العمل المقترح لاحقًا

- تحسين استخراج العربية وترتيب الأسطر دون عكس الأرقام والأجزاء الإنجليزية عشوائيًا.
- تجربة Poppler لقراءة النص مع الحفاظ على ترتيب الصفحة.
- OCR محلي باستخدام Tesseract وبيانات `ara+eng` عندما تفشل القراءة النصية.
- حفظ النص الخام والمعالج منفصلين خارج wwwroot، مع ترقيم الصفحات.
- دعم التاريخ الملتصق بالكلمات، وإبقاء رفض التاريخ المختلف فعليًا.
- عرض التاريخ المستخرج واقتباس الدليل ورقم الصفحة في المراجعة، وصياغة رسالة
  تعذر التحقق بحيث لا تجزم بأن التاريخين مختلفان دون إثبات.
- إعادة جلب ملفات PDF القديمة عند إعادة المحاولة بدل معالجة النص المشوّه نفسه.

## متطلبات مقترحة تحتاج اعتمادًا وتحققًا عند التنفيذ

على Debian/Ubuntu، بواسطة مسؤول الجهاز:

```sh
apt-get update
apt-get install poppler-utils tesseract-ocr tesseract-ocr-ara tesseract-ocr-eng
pdftotext -v
pdftoppm -v
tesseract --list-langs
```

عند تنفيذ المرحلة، يجب أن تظهر `ara` و`eng`. على Windows استخدم توزيعات موثوقة للأداتين
وأضف مسار التنفيذ لحساب الخدمة أو اضبط المسارات الكاملة في البيئة:

- `Pdf__TextExecutable`: مسار `pdftotext.exe`، الافتراضي `pdftotext`.
- `Pdf__RenderExecutable`: مسار `pdftoppm.exe`، الافتراضي `pdftoppm`.
- `Pdf__OcrExecutable`: مسار `tesseract.exe`، الافتراضي `tesseract`.
- `Pdf__OcrDataPath`: مجلد `tessdata` إذا لم يكن مسار Tesseract الافتراضي مناسبًا.
- `Pdf__EnableOcr`: الافتراضي true؛ false يوقف OCR ويطلب مراجعة النص غير المقروء.
- `Pdf__TextArchivePath`: مجلد خاص خارج wwwroot يحتفظ بالنص الخام والنص المقروء؛
  الافتراضي `logs/pdf-text` تحت مجلد ملفات التطبيق. امنح حساب الخدمة صلاحية الكتابة.

المقترح بعد تنفيذ المرحلة وإعداد المتطلبات: إعادة تشغيل العامل. النص الخام محفوظ باسم SHA256 لمحتوى الملف
متبوعًا بـ`.original.txt`، والنص المعالج بـ`.readable.txt`. النص الخام لا يُرسل للنموذج.
تُحذف ملفات العمل المؤقتة بعد المحاولة. احتفظ بأرشيف النصوص خارج الويب العام
واضبط سياسة احتفاظ مناسبة، مع تحديث إصدارات أدوات معالجة المستندات باستمرار.

يُحد وقت العملية الخارجية بـ45 ثانية، والمستند بـ3 دقائق، والصورة بـ2500 بكسل
لأكبر بُعد، والنص المعالج بـ2 MB. فشل الأدوات أو غياب بيانات العربية ينتج مراجعة
واضحة؛ لا تُستخدم قراءة معكوسة بديلًا ناجحًا. تشغيل الأدوات لا يغير إعدادات المصدر.

تتضمن مدخلات النموذج ترقيم الصفحات `[PDF PAGE n]`. تُعرض في صفحة الطلب قيمة الموعد
واقتباس الدليل ورقم الصفحة الذي أعاده النموذج إن وجد. الاقتباس ليس إثباتًا مستقلًا
إلا بعد مطابقته مع النص المحفوظ؛ رقم الصفحة معلومة من النموذج.

السلوك المقترح لزر «إعادة المحاولة» للطلبات القديمة: ملفات PDF ومرفقاتها تُجلب مجددًا بدل إعادة
معالجة النص المعكوس المحفوظ. تبقى النسخ السابقة ضمن سجل المراجعات الموجود.
لا يلزم تغيير قاعدة البيانات أو مفتاح AI إضافي.

## معايير القبول قبل الاعتماد

اختبار ملفات عربية نصية ومصورة ومختلطة اللغات ومتعددة الأعمدة والصفحات؛
التحقق من عدم تخمين الكلمات والأسماء، ومقارنة OCR بصور الصفحات.
اختبار التواريخ الملتصقة والأرقام العربية وأسماء الأشهر والتواريخ المخالفة فعليًا.
اختبار غياب الأدوات وبيانات العربية والملفات التالفة وحدود الوقت والحجم والإلغاء.
البناء التجريبي السابق نجح، لكن الملف المرجعي لم يُختبر فعليًا بسبب HTTP 403،
ولم تتوفر بيانات OCR العربية في بيئة العمل. لا يعد ذلك اعتمادًا لصحة الاستخراج.
