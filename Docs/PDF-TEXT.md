# قراءة PDF وOCR — التنفيذ والتشغيل

الحالة: منفذ في الكود بتاريخ 16 أكتوبر 2026، بعد طلب المستخدم بدء هذه المرحلة. يحل هذا التوثيق محل المقترح المؤجل. لا يحتاج التغيير مهاجرة جديدة لقاعدة البيانات أو مفتاح AI إضافيًا. لم تُثبت أدوات على جهاز المستخدم أو استضافته أثناء هذه المهمة.

## ماذا أصبح يعمل؟

- تنزيل PDF مباشر أو حتى ثلاثة مرفقات PDF في الإعلان، مع بقاء فحص النطاقات العامة والتحويلات وحد الحجم.
- قراءة طبقة النص بواسطة Poppler مع فصل الصفحات. النص العربي لا يُعكس يدويًا: يُقرأ من صورة الصفحة باستخدام Tesseract بالعربية والإنجليزية لتجاوز مشاكل ترتيب الحروف وخرائط الخطوط. تُستخدم OCR أيضًا للصفحة المصورة أو غير المقروءة، بينما تبقى الصفحة الإنجليزية النصية على مسار النص.
- المستند المختلط يُعالج صفحة بصفحة؛ الصفحة التي تتضمن صورة تُقرأ بصريًا أيضًا حتى إن احتوت طبقة نص، كي لا يُتجاهل محتوى الصورة. لا ينجح بمجرد وجود نص في صفحة واحدة مع تجاهل الصفحات المصورة الأخرى. الصفحة الخالية فعلًا لا تختلق نصًا؛ المستند الخالي أو شديد القصر يُحال للمراجعة.
- حفظ PDF الأصلي، ونص PdfPig/Poppler الخام، والنص المقروء، وتقرير طريقة القراءة والثقة لكل صفحة. المحتوى المعالج فقط يُرسل إلى AI، وليس نسختين متعارضتين من النص.
- صفحة عنصر المصدر في الإدارة تعرض تنزيلات الأرشيف، ورقم صفحة دليل التاريخ عندما يطابق الاقتباس النص المحفوظ. الصفحة محسوبة من الدليل الفعلي، وليست تخمينًا من النموذج.
- «إعادة المحاولة» لملف PDF أو إعلان له مرفقات تعيد الجلب والقراءة، وتمسح استخراج AI السابق. النص السابق يبقى في سجل نسخ المحتوى عند استبداله؛ لا تمسح الفرص القديمة أو قرارات الأدمن. تبقى حماية المنشور والمؤرشف والقرارات اليدوية كما في المرحلة السابقة.

### متى يذهب إلى المراجعة؟

غياب الأدوات أو بيانات اللغة، الملف التالف أو المحمي بكلمة مرور، انخفاض جودة OCR، تجاوز الحدود أو تعذر كتابة الأرشيف ينتج سبب مراجعة واضحًا. لا يُرسل مستند ناقص الصفحات إلى AI على أنه قراءة ناجحة. في الإدارة افتح «التفاصيل التقنية» لمعرفة الأداة أو الصفحة التي فشلت؛ قد تتعذر تنزيلات الأرشيف نفسه إذا كانت صلاحياته خاطئة.

**OCR يتطلب مراجعة بصرية افتراضيًا قبل النشر** حتى عندما تنجح القراءة. في الاختبارات قرأ Tesseract اسم جهة بشكل غير دقيق رغم متوسط ثقة يتجاوز 90%؛ الثقة ليست إثبات صحة الأسماء أو الأرقام. يظهر الاستخراج للمراجعة، ويمكن للأدمن مقارنة الملف الأصلي وتصحيح البيانات واعتمادها. `Pdf:RequireOcrReview=false` يسمح بمسار الاعتماد المعتاد بعد تحقق الأدلة؛ استخدمه فقط إذا قبلت دقة عيناتك. لا يغيّر هذا الخيار نص OCR نفسه ولا يضمن خلوه من الأخطاء. بعد تغيير السياسة أعد المحاولة لجلب النص بالسياسة الجديدة.

التحقق من نوع التاريخ وقيمته واقتباسه يبقى مطبقًا. مطابقة رقم مستخرج مع نص OCR تثبت المطابقة مع التفريغ، ولا تثبت مطابقته للصورة؛ لذلك توجد المراجعة البصرية الافتراضية. الصور المائلة أو منخفضة الجودة، والأعمدة المعقدة، والجداول قد تحتاج مراجعة وتصحيحًا يدويًا. لا يُخمّن النص أو يُحوّل من هجري إلى ميلادي.

## المطلوب منك على Windows المحلي

1. ثبّت توزيعة Poppler لـWindows تتضمن `pdftotext.exe` و`pdftoppm.exe` وكل DLLs التابعة لها. ضعها مثلًا في `C:\Tools\Poppler\Library\bin`. لا يكفي نسخ ملفي exe وحدهما.
2. ثبّت Tesseract 5.x x64، مثلًا في `C:\Program Files\Tesseract-OCR`. تأكد أن `tessdata` يتضمن `ara.traineddata` و`eng.traineddata` المتوافقين مع Tesseract. بيانات `tessdata_fast` إصدار 4.1.0 متوافقة مع Tesseract 5 في فحوص هذه المهمة.
3. حدد مجلد أرشيف خاص خارج `wwwroot`، مثل `C:\HiringPsData\PdfText`. من نفس PowerShell الذي ستشغّل منه الموقع والعامل:

```powershell
.\scripts\configure-pdf.ps1 `
    -PopplerDirectory 'C:\Tools\Poppler\Library\bin' `
    -TesseractDirectory 'C:\Program Files\Tesseract-OCR' `
    -OcrDataDirectory 'C:\Program Files\Tesseract-OCR\tessdata' `
    -ArchiveDirectory 'C:\HiringPsData\PdfText'
```

السكربت يفحص الملفات، ويضبط متغيرات PDF لهذه الجلسة فقط، ويشغّل فحص الأدوات واللغات والكتابة. لا يغيّر SQL أو AI أو الإعدادات العامة للجهاز. شغّل الموقع والعامل من الجلسة نفسها، أو انقل قيم PDF إلى إعدادات تشغيلهما في IDE. عند فتح جلسة جديدة أعد السكربت أو استخدم إعدادات دائمة خاصة بمشروعي Web وWorker.

لفحص ملف تملكه دون نشر أو اتصال AI/SQL:

```powershell
dotnet run --project src/HiringPs.Worker -c Release -- --pdf-check
dotnet run --project src/HiringPs.Worker -c Release -- --pdf-read 'C:\Samples\tender.pdf'
```

يطبع الأمر الثاني طريقة كل صفحة والثقة ومسار الأرشيف، ويكتب النصوص في الأرشيف. جرّب بعدها «إعادة المحاولة» لإعلان PDF قديم في اللوحة وافتح رقم صفحة دليل التاريخ والتنزيلات.

### مصادر الأدوات وبيانات العربية

- [مشروع Poppler](https://poppler.freedesktop.org/) و[توزيعة Windows المجتمعية](https://github.com/oschwartz10612/poppler-windows/releases). توزيعة Windows ليست حزمة منشورة من هذا المشروع؛ راجع مصدرها ومتطلباتها وإصدارها قبل تثبيتها.
- [إرشادات تثبيت Tesseract](https://tesseract-ocr.github.io/tessdoc/Installation.html)، وتتضمن روابط Windows مثل UB Mannheim.
- [بيانات العربية الرسمية السريعة](https://github.com/tesseract-ocr/tessdata_fast/blob/4.1.0/ara.traineddata) و[الإنجليزية](https://github.com/tesseract-ocr/tessdata_fast/blob/4.1.0/eng.traineddata). نزّل الملف الثنائي من Raw، لا صفحة HTML.

SHA256 لملف العربية 4.1.0 المستخدم في الاختبار:

```text
e3206d3dc87fd50c24a0fb9f01838615911d25168f4e64415244b67d2bb3e729
```

```powershell
Get-FileHash 'C:\Program Files\Tesseract-OCR\tessdata\ara.traineddata' -Algorithm SHA256
```

لا Python أو Node أو اشتراك OCR سحابي مطلوب لتشغيل هذه الميزة. تبقى متطلبات الموقع والعامل وAI المعتادة كما هي.

## المطلوب على استضافة Windows VPS / IIS

تحتاج VPS يسمح بتثبيت وتشغيل برامج خارجية. الاستضافة المشتركة التي تمنع تشغيل العمليات لا تكفي لهذا المسار؛ يجب أن يعمل العامل على جهاز يسمح بذلك، ويشارك الأرشيف مع الموقع إذا أردت تنزيل الأدلة من الإدارة.

1. جهّز حزم Web وWorker الجديدة بأداة النشر الحالية. ثبّت أدوات Poppler/Tesseract واللغتين على VPS نفسه؛ ملفات publish لا تتضمن الأدوات أو traineddata تلقائيًا.
2. أنشئ مجلدًا دائمًا خارج مجلدي النشر، مثل `C:\Apps\HiringPs\Data\PdfText`، حتى لا يضيع الأرشيف عند استبدال حزمة البرنامج.
3. لحساب خدمة العامل: قراءة/تنفيذ مجلدات الأدوات وDLLs، وقراءة tessdata، وكتابة المجلد المؤقت والأرشيف. لحساب IIS: قراءة الأرشيف إذا أردت التنزيل من لوحة الإدارة. لا تجعل الأرشيف موقع IIS أو مجلدًا افتراضيًا عامًا. اضبط ACL لحساباتك الفعلية، ولا تمنح Everyone وصولًا.
4. بعد تثبيت خدمة العامل الموجودة أصلًا، شغّل PowerShell كمسؤول:

```powershell
.\configure-pdf.ps1 `
    -PopplerDirectory 'C:\Tools\Poppler\Library\bin' `
    -TesseractDirectory 'C:\Program Files\Tesseract-OCR' `
    -OcrDataDirectory 'C:\Program Files\Tesseract-OCR\tessdata' `
    -ArchiveDirectory 'C:\Apps\HiringPs\Data\PdfText' `
    -WorkerDirectory 'C:\Apps\HiringPs\Worker' `
    -ServiceName 'HiringPsCollector'
```

يحفظ السكربت متغيرات PDF فقط في إعداد Environment للخدمة القائمة، ويُبقي إعدادات SQL وAI والمتصفح وبقية المتغيرات. لا يعيد تشغيل الخدمة. الفحص يجري بحساب PowerShell الحالي، وليس تلقائيًا بحساب الخدمة؛ تحقق أيضًا من صلاحيات حساب الخدمة.

5. اضبط **نفس** `Pdf__TextArchivePath` للموقع في IIS، أو `Pdf:TextArchivePath` في إعداد Production خارجي مناسب. الموقع يحتاج هذا المسار لقراءة الأدلة؛ العامل هو من ينفذ الاستخراج. لا تنسخ ملف إعداد كاملًا فوق اتصالك أو أسرارك. مثال يضاف داخل عنصر `aspNetCore` الحالي في `web.config`، مع الإبقاء على إعداداته الأخرى وعدم تكرار `environmentVariables` إذا كان موجودًا:

```xml
<environmentVariables>
    <environmentVariable name="Pdf__TextArchivePath" value="C:\Apps\HiringPs\Data\PdfText" />
</environmentVariables>
```

احتفظ بضبط IIS هذا عند تحديث ملف النشر لاحقًا.
6. أعد تشغيل خدمة العامل بعد إكمال الضبط، وأعد تشغيل Application Pool إذا غيّرت إعدادات الموقع:

```powershell
Restart-Service HiringPsCollector
Get-Service HiringPsCollector
```

من مجلد Worker المنشور، ومن حساب له الصلاحيات نفسها:

```powershell
.\HiringPs.Worker.exe --pdf-check
.\HiringPs.Worker.exe --pdf-read 'C:\Samples\tender.pdf'
```

الأمر المنشور لا يحتاج SDK، ولا مفتاح AI أو SQL للفحص. هذه أوامر اختبار أدوات وقراءة محلية؛ لا تبدأ جولة جمع ولا تنشر بيانات. نجاح الفحص كمسؤول لا يثبت صلاحيات حساب الخدمة؛ أعد تجربة الجمع الفعلية من اللوحة وتحقق من تنزيل الأدلة بعد إعادة التشغيل.

المرجع العام: [النشر اليدوي](MANUAL-DEPLOYMENT.md).

## الإعدادات والحدود

يمكن ضبطها بمتغيرات البيئة التالية، أو بمفاتيح JSON المقابلة داخل قسم `Pdf`:

| المتغير | الافتراضي / الغرض |
| --- | --- |
| `Pdf__TextExecutable` | `pdftotext`؛ استخدم المسار الكامل على Windows |
| `Pdf__RenderExecutable` | `pdftoppm`؛ استخدم المسار الكامل على Windows |
| `Pdf__OcrExecutable` | `tesseract`؛ استخدم المسار الكامل على Windows |
| `Pdf__OcrDataPath` | مجلد tessdata الافتراضي للأداة إذا لم يضبط |
| `Pdf__TextArchivePath` | `logs/pdf-text` تحت مجلد البرنامج؛ اضبط مسارًا مطلقًا مشتركًا لـWeb وWorker |
| `Pdf__EnableOcr` | `true`؛ تعطيله يحيل الصفحات العربية والمصورة للمراجعة |
| `Pdf__RequireOcrReview` | `true`؛ اشتراط المراجعة البصرية للنص المقروء بـOCR |
| `Pdf__ProcessTimeoutSeconds` | 45 ثانية؛ قابل للتقليل من 1 إلى 45، وليس للزيادة |

الملف حتى 8 MB و40 صفحة، وحتى ثلاثة مرفقات PDF للإعلان. التنزيل كله له 40 ثانية؛ المعالجة لها ميزانية 3 دقائق للمستند، مع مهلة قصيرة إضافية لإنهاء العمليات وحفظ تقرير الفشل. أقصى بُعد للصورة 2500 بكسل، وحد كل مخرج نصي 2 MB. تتوقف العمليات الخارجية وشجرتها عند الإلغاء أو انتهاء المهلة. تُحذف ملفات العمل المؤقتة بعد المحاولة؛ قد تبقى ملفات مقفلة إذا منع النظام حذفها، ضمن مجلد `hiring-pdf-*` في temp.

الأرشيف بأسماء SHA256 للمحتوى:

```text
<HASH>.pdf             نسخة الملف الأصلي
<HASH>.original.txt    النص الخام من قارئي النص، مع أرقام الصفحات
<HASH>.readable.txt    النص الذي يعود لمسار الاستخراج، مع علامات الصفحات
<HASH>.json            آخر تقرير قراءة، Complete وRequiresVisualReview وثقة كل صفحة
```

إعادة نفس الملف تحدث تقريره ونصوصه؛ اختلاف البايتات ينتج hash جديدًا. عند الفشل يكون `Complete=false`، والنص الجزئي للتشخيص فقط ولا يُرسل إلى AI. التحميل من الإدارة محمي بحساب الأدمن. خذ نسخة احتياطية من الأرشيف مع قاعدة البيانات وراقب المساحة. سياسة تنظيف التشخيص الحالية لا تحذفه تلقائيًا؛ حذف أرشيف قديم يحذف وسيلة المقارنة البصرية لذلك الملف، لذا حدد احتفاظًا يناسب سجلاتك قبل الحذف اليدوي.

## Debian/Ubuntu وبيئة التطوير السحابية

على جهاز تديره وبحساب مسؤول:

```bash
sudo apt-get update
sudo apt-get install poppler-utils tesseract-ocr tesseract-ocr-ara tesseract-ocr-eng
pdftotext -v
pdftoppm -v
tesseract --list-langs
```

يجب ظهور `ara` و`eng`. عند استخدام tessdata خاص اضبط `Pdf__OcrDataPath`. امنح حساب العامل الكتابة إلى temp والأرشيف، وحساب الويب القراءة فقط إذا احتاج التنزيل. نفس أوامر Worker تعمل باستخدام `dotnet HiringPs.Worker.dll` بعد النشر.

## ما اختُبر وما يحتاج تجربة لديك؟

- نجح بناء Release، و41 فحص PDF بالأدوات الفعلية، و39 فحصًا لمسار المعالجة السابق (80 فحصًا إجمالًا). نجح أمر العامل `--pdf-check` وقراءة المستند المختلط محليًا دون SQL أو AI. اختُبر Tesseract 5.5.0 وpdftotext 25.03.0 على Linux؛ لم تُختبر توزيعات Windows هنا.
- اختبارات `--pdf-check` في مشروع Checks تشغّل الأدوات الحقيقية على ملفات إنجليزية نصية، وعربية نصية، وعربية مصورة، ومستند مختلط. تشمل رقم صفحة الدليل، والأرشيف، والملف الخالي والمشفر، وحدود الحجم والصفحات، والأداة المفقودة، واللغة المفقودة، وتعطيل OCR، والإلغاء، وإنهاء عملية تجاوزت المهلة، والتواريخ العربية الملتصقة.
- الملفات الاختبارية صناعية ملتزمة بالمستودع وليست إعلانات حقيقية أو بيانات شخصية. راجع [شرح العينات](../tests/HiringPs.Checks/Fixtures/Pdf/README.md).
- رابط الهلال الأحمر المرجعي أعاد HTTP 403 أثناء هذه المهمة؛ لم نختبر نجاح قراءة ذلك الملف الفعلي. لا تحاول أدوات النص تجاوز حظر تنزيل المصدر؛ يلزم رابط متاح أو نسخة يمكنك تنزيلها بصورة مشروعة.
- اختبار Windows وIIS وحساب الخدمة، والربط الوظيفي للإدارة مع SQL، ما زال يحتاج بيئتك. نجاح Linux لا يثبت إعداد الاستضافة. اختبر إعلانًا نصيًا وآخر مصورًا من مصادرك قبل الاعتماد.

```powershell
dotnet build HiringPs.sln -c Release
dotnet run --project tests/HiringPs.Checks -c Release -- --pdf-check
dotnet run --project tests/HiringPs.Checks -c Release -- --workflow-check
```
