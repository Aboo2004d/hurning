# الحسابات والباقات والدفع وتليجرام — القرارات المعتمدة

الحالة: توثيق معتمد للمناقشة، وليس تنفيذًا أو إثبات جاهزية. التاريخ: 17 أكتوبر 2026.
هذا الملف يتقدم على القرارات التاريخية المتعارضة في PROJECT-PLAN.md. لا يتغير كود التطبيق أو قاعدة البيانات ضمن هذه المهمة.

## 1. الهوية والبنية واللغات

- الاسم الجديد المعتمد: «التوظيف في فلسطين». تغيير نصوص الواجهة وSEO ما زال عملًا تنفيذيًا لاحقًا؛ الاسم الإنجليزي النهائي يحتاج تحديدًا.
- فصل مسؤوليات الصفحات في Controllers واضحة، مع Area/Admin وLayout وهيدر خاصين، ومساحة مستقلة للمستخدم. الفصل حسب مسؤولية الصفحة، ولا يقتضي Controller لكل action تقني.
- جميع الواجهات الجديدة ورسائل البوت بالعربية والإنجليزية.
- اللغة الصريحة الصحيحة في أول الرابط /ar أو /en هي الأولوية وتُحفظ في الكوكي. عند غيابها أو خطئها: آخر لغة محفوظة، ثم لغة المتصفح المدعومة، ثم العربية.
- تصحيح /an/Home/Contact إلى /ar/Home/Contact عند تفضيل العربية، دون إسقاط المسار أو معاملات الرابط. لا تُحوّل لغة /en الصحيحة بسبب كوكي عربي.
- تبديل اللغة يبقي الصفحة والبحث والفلاتر والترقيم ومعاملات الرابط، في العام والأدمن والمستخدم. روابط البوت بلغة المستخدم وقت الإرسال.
- صفحات أخطاء بهوية الموقع: 404 و403 و500 وانتهاء مهلة الانتظار، مع إعادة المحاولة المناسبة ودون تفاصيل داخلية.
- شاشة تحميل مؤقتة بشعار السلة وحركة بسيطة، تختفي آليًا؛ ليست صفحة ترحيب مستقلة. يلزم تنفيذ لا يحجب المحتوى عند تعطل JavaScript أو الحركة.

## 2. التسجيل والحساب وتليجرام

- تسجيل بالبريد وكلمة المرور والاسم ورقم الجوال الخاص بتليجرام. التسجيل يبدأ بعضوية مجانية، دون اختيار باقة أو دفع خلال التسجيل.
- لا تحقق بالبريد ولا موافقة إدارة للتسجيل العادي ولا زر واتساب. تفعيل الحساب بعد ربط تليجرام والتحقق، ويشمل ذلك الحساب المجاني.
- رابط بوت فريد مربوط بطلب التسجيل؛ يبدأ المستخدم البوت ويشارك رقمه من زر مشاركة جهة الاتصال الخاصة به. يتحقق السيرفر من ملكية جهة الاتصال وتطابق الرقم ثم يربط chat بالحساب؛ لا يُفترض أن البوت يستطيع المراسلة برقم الهاتف وحده.
- رمز تحقق من 6 أرقام، صالح 5 دقائق، إعادة إرسال بعد دقيقة. حد محاولات وإعادة إرسال، واستخدام واحد للرمز؛ القيم التفصيلية للحدود تُضبط أثناء التنفيذ.
- حساب تليجرام واحد لحساب موقع واحد. تغيير الربط يتطلب التحقق من الحالي ثم الجديد. فقد الوصول: استعادة عبر الإدارة بعد تحقق الهوية، مع توثيق الإجراء؛ إجراءات إثبات الهوية التفصيلية تحتاج تحديدًا.
- الدخول بالبريد وكلمة المرور. استعادة كلمة المرور برمز عبر تليجرام المرتبط، لا البريد.
- باقتي، مدفوعاتي، تفضيلاتي، إعدادات الحساب، المحفوظات متاحة للعضو المجاني والمشترك. التنبيهات المدفوعة تتطلب باقة سارية بصلاحيتها.

## 3. إتاحة الفرص والباقات

- تتحكم الإدارة بالإتاحة العامة لكل نوع فرصة، لا لكل إعلان: الوظائف والتدريب والعطاءات والمناقصات.
- العناوين والقوائم تظهر للجميع كما الآن؛ زر التفاصيل يغيب عمن لا يملك حقها. حماية الرابط المباشر لازمة أيضًا، مع توضيح السبب وزر الباقات للمسجل والدخول للزائر، وإظهار الباقات المناسبة.
- النوع العام متاح للجميع. إتاحة التفاصيل للعامة لا تمنح تنبيهات مدفوعة تلقائيًا.
- في كل باقة ولكل نوع خياران مستقلان: عرض التفاصيل، واستقبال التنبيهات. مزايا الباقات يمكن أن تختلف، وليست المدة والسعر فقط.
- الإدارة تضبط الاسم والوصف بالعربية والإنجليزية، السعر بالشيكل، المدة بالأيام، المزايا، ترتيب العرض، ووسم مثل «الأكثر طلبًا».
- 5 شيكل و30 يوم مثال ابتدائي قابل للتعديل، وليسا قيدًا ثابتًا. الشيكل عملة العرض والدفع الوحيدة؛ لا اختيار عملات أو تحويل.
- إخفاء الباقة يمنع شراءها جديدًا ولا يلغي حقوق المشتريات الحالية أو المجدولة.
- صفحة باقتي تظهر «مجانية» أو الباقة الحالية، تاريخ الانتهاء والأيام المتبقية والباقات المجدولة، ومنها اختيار الباقة والدفع.

## 4. دورة الاشتراك

- يبدأ الاشتراك عند تأكيد الدفع إذا لم يوجد اشتراك سابق ساري؛ المدة أيام فعلية وليست شهرًا تقويميًا.
- تجديد الباقة نفسها دون تغيير إصدارها يضيف مدتها إلى المتبقي: 3 + 30 = 33 يومًا. التجديد بعد الانتهاء يبدأ من تأكيد الدفع.
- شراء باقة مختلفة أثناء الاشتراك يجدولها بعده. شراء باقات أخرى يضيفها لنهاية التسلسل.
- تغيير السعر أو المدة أو المزايا يُنتج إصدار عرض جديدًا للمشتريات اللاحقة ويعامل شراءه كباقة جديدة مجدولة. المشتريات الحالية والمجدولة تحتفظ بالنسخة المشتراة حتى الانتهاء.
- التجديد يدوي بعملية جديدة؛ لا خصم آلي. عند الانتهاء يعود الحساب مجانيًا مع بقاء التفضيلات والمحفوظات.
- تذكير عبر تليجرام قبل الانتهاء بثلاثة أيام ورسالة عند الانتهاء. يلزم إعادة تقييم موعد التذكير عند التجديد أو التجميد لتجنب رسالة انتهاء غير صحيحة.
- الإدارة تمنح وتمدد وتوقف الاشتراك يدويًا مع سبب وسجل تدقيق.
- تعليق الحساب يمنع الدخول والتنبيهات ويظهر سببه للمستخدم. تختار الإدارة استمرار عد المدة أو تجميدها؛ التجميد يؤجل مواعيد الاشتراك والباقات المجدولة بمقداره، واستمرار العد يبقيها كما هي.
- رفع التعليق يعيد الصلاحيات للاشتراك الساري ويحترم إيقاف المستخدم السابق للتنبيهات.

## 5. الخصومات والدفع

- بوابتان: لحظة وجوال باي. إدارة تمكين/تعطيل/إخفاء كل بوابة، ولا تظهر إلا الجاهزة والمفعلة. ملفات التكامل سيقدمها المستخدم لاحقًا؛ لا مفاتيح سرية في التوثيق.
- كود خصم نسبي حتى 100% مرتبط بعرض محدد، مع انتهاء وحد استخدام إجمالي ومرة لكل مستخدم. يصلح للشراء أو التجديد إذا استوفى الشروط.
- الخصم الكامل يفعّل/يجدد/يجدول وفق القواعد نفسها دون بوابة دفع، مع سجل طلب واضح.
- مراجعة الطلب قبل الدفع: الباقة والمزايا والمدة والخصم والمبلغ النهائي وبداية الاشتراك. سياسة عدم الاسترداد واضحة وخانة موافقة إلزامية قبل البدء.
- لا استرداد ضمن النطاق المعتمد. موافقة المستخدم على الشروط وسياسة عدم الاسترداد تُسجل مع العملية وإصدار الشروط كمتطلب تنفيذ.
- صلاحية عملية الدفع 10 دقائق أو المدة الأقصر لدى البوابة. حفظ نسخة السعر والمزايا عند إنشائها؛ لا تغييرها بسبب تعديل الباقة أثناء الانتظار.
- انتهاء المهلة محليًا لا يلغي واقعة خصم لاحقة: أي دفع يتحقق السيرفر من نجاحه يُعتمد حتى لو وصل التأكيد متأخرًا. تفسير زمن الصلاحية مع البوابة يحتاج اختبار التكامل.
- صفحة الرجوع من البوابة ليست إثبات دفع. تحقق API وwebhook الموثق حسب عقد المزود، ومطابقة الطلب والمبلغ والعملة، وتفعيل واحد فقط لكل عملية مهما تكررت الرسائل أو الاستعلامات.
- إعادة المحاولة تنشئ عملية جديدة وتبقي السابقة في السجل. إذا نجحت محاولتان فعليًا يجب تسجيلهما وعدم إسقاط أي خصم؛ معالجة هذه الحالة الخاصة تحتاج قرارًا قبل إطلاق الدفع الحقيقي، دون افتراض سياسة استرداد.
- رسالة تأكيد تليجرام تشمل الباقة والمبلغ والبداية والنهاية ولو كانت مجدولة.
- مدفوعاتي: العمليات وحالاتها والمبلغ والمرجع والتفاصيل. لوحة الإدارة: المدفوعات والبوابات والبحث بالمرجع والتصفية، ومتابعة العمليات غير المحسومة آليًا مع تنبيه الإدارة.

## 6. التحقق والمراجعة اليدوية للدفع

- زر التحقق من الدفع بالموقع وأمر البوت `/payment_status orderId`؛ الشرطة السفلية بدل الشرطة غير المدعومة في اسم أمر تليجرام.
- لا يسمح رقم الطلب وحده بالاستعلام: يجب أن يخص الطلب الحساب المرتبط. حدود طلبات وتفادي الاستعلامات المتزامنة أثناء التنفيذ.
- السيرفر يستعلم API البوابة ويحدّث العملية والاشتراك أولًا، ثم يعرض أو يرسل النتيجة للبوت. لا يدّعي البوت حالة نجاح قبل حفظها.
- الإدارة تستطيع إعادة الاستعلام والتحقق من اشتراك المستخدم، واعتماد الاشتراك يدويًا حتى لو تعذر تأكيد API، بشرط سبب وإثبات دفع وتسجيل المسؤول والتاريخ.
- يميز السجل بين إثبات المزود والاعتماد اليدوي؛ وصول تأكيد لاحق لا يكرر الاشتراك.
- زر «تم الخصم ولم يتفعّل اشتراكي» يفتح طلب مراجعة مرتبطًا بالعملية. الملاحظة وصورة إثبات الدفع اختياريتان للمستخدم؛ هذا لا يلغي وجوب توثيق إثبات الاعتماد اليدوي من الإدارة.
- متابعة الإدارة حتى الحل، وإشعار المستخدم عبر تليجرام بالنتيجة وسبب القرار. المرفقات خاصة بصاحب الطلب والإدارة مع تحقق النوع والحجم ومنع تنفيذها.

## 7. التفضيلات والإرسال والمحفوظات

- تليجرام وحده لتنبيهات الفرص. إرسال عند النشر الجديد، لا بمجرد الاكتشاف ولا إرسال تاريخ قديم. الفورية مرتبطة بزمن الجمع والمعالجة وتوفر العامل.
- تفضيلات متعددة من قوائم الأنواع والمجالات والمواقع الموحّدة، دون نص حر. يكفي أحد المجالات وأحد المواقع مع تطابق النوع وصلاحية الباقة. المجال أو الموقع الفارغ يعني الجميع.
- تغيير التفضيلات وإعادة تفعيل التنبيهات يؤثران في الفرص الجديدة بعدهما فقط، دون تعويض فترة الإيقاف أو إرسال النتائج السابقة.
- إيقاف مؤقت من لوحة المستخدم أو /stop دون إيقاف مدة الاشتراك. إعادة التفعيل من اللوحة برمز جديد يرسله البوت، بنفس مدة وصلاحية رموز التحقق.
- /stop يوقف تنبيهات الفرص وتذكيرات المحفوظات؛ لا يوقف رسائل التحقق والدفع والاشتراك ومراجعة الدفع.
- /start للربط، وللمرتبط يعرض حالة الربط والتنبيهات وزر اللوحة. /status للباقة والانتهاء وحالة التنبيهات. /help للأوامر وأزرار باقتي وتفضيلاتي. إضافة /payment_status للاستعلام المذكور أعلاه.
- طابور إرسال دائم مع إعادة المحاولة وحالة تسليم وأخطاء للإدارة، وإشعار داخل حساب المستخدم عند حظر البوت أو تعطل الربط. لا تكرار مقصود للفرصة نفسها؛ يلزم التعامل مع غموض نتيجة الشبكة دون ادعاء ضمان exactly-once من Telegram.
- المحفوظات للمجاني والمدفوع، مع بقاء حماية التفاصيل. تذكير واحد قبل انتهاء تقديم الفرصة المحفوظة بيوم إذا الموعد معروف والباقة تسمح بتنبيه النوع والتنبيهات مفعلة. خيار مستقل لتشغيل تذكيرات المحفوظات.

## 8. إدارة المستخدمين والتدقيق

- صفحة مستخدمين: بحث بالاسم والبريد والجوال؛ تصفية بالباقة وحالة الحساب وربط تليجرام.
- صفحة اشتراكات: الحالية والمجدولة والمنتهية؛ بحث وتصفية ومنح وتمديد وإيقاف يدوي.
- سجل تدقيق لجميع إجراءات الإدارة على الحساب والاشتراك والدفع: المسؤول والإجراء والسبب والتاريخ. لا يسجل مفاتيح أو رموز تحقق صريحة.
- الجداول الجديدة تتبع القاعدة الحالية: 10 سجلات بطلب خادم لكل صفحة، مع الحفاظ على الفلاتر.

## 9. المقارنة بالكود والخطة الحالية

هذه مقارنة قراءة ملفات، لا اختبار تشغيل أو SQL أو دفع حي.

| المجال | الموجود في الكود | المتبقي |
|---|---|---|
| الحسابات | IdentityUser؛ AccountController يسمح دخول Admin فقط | تسجيل الأعضاء، التحقق والاستعادة، ملف المستخدم والتعليق |
| الفصل | Controllers عامة وملفات Admin جزئية في Controllers، و_AdminNav مشترك | Areas مستقلة، Layout وهيدر الإدارة والمستخدم، فصل مسؤوليات HomeController |
| اللغات | موارد ar/en، كوكي اللغة وRequestLocalization؛ مسار MVC بلا بادئة لغة | مسارات /ar و/en، التصحيح والأولوية، حفظ الحالة وروابط SEO والعودة الآمنة |
| الإتاحة | HomeController.Details يعرض التفاصيل العامة | صلاحيات النوع العامة وصلاحيات الباقة على الخادم والواجهة |
| البيانات | HiringDb فيه فرص ومصادر وتدقيق ورسائل وتتبّع أدوات وبرومبت | جداول باقات وإصدارات واشتراكات وطلبات ومدفوعات وخصومات وتفضيلات وربط بوت وطابور ومراجعات |
| الدفع والبوت | لا خدمات دفع أو Telegram أو نماذج اشتراك في Core الحالي | التكاملان والتوثيق والاختبارات وحفظ الحالات والإرسال |
| الأخطاء والتحميل | Error action وShared/Error وExceptionHandler عام | حالات الأخطاء الجديدة وشاشة التحميل المتاحة |
| الترقيم | AdminPager بحجم 10 وواجهات ترقيم حالية | تطبيقه على جداول المستخدمين والاشتراكات والمدفوعات الجديدة |
| التشغيل | Worker مستقل، heartbeat ومراقبة أدوات، جمع ومعالجة وفرص وتدقيق | مهام الاستحقاق والطابور والتذكيرات وتسوية الدفع، وقياسها دون تعطيل الجمع |

مصادر المقارنة: AccountController.cs وHomeController.cs وProgram.cs في Web، Database.cs وDomain.cs في Core، وViews/Shared وModels/AdminPagination.cs. لا يعني وجود Identity أو Audit أن وظائف العضوية مكتملة.

الخطة القديمة: المرحلة الثالثة تنبيهات مجانية بالبريد وتوثيق بريد؛ الرابعة دفع مقابل التنبيهات وحدها مع بقاء كل التفاصيل مجانية. هذه القرارات مستبدلة بالمذكور هنا: تحقق تليجرام للجميع، تنبيهات للمشترك، ومزايا تفاصيل وتنبيهات لكل باقة. لا مزود بريد أو SPF/DKIM مطلوب لهذا النطاق.
المرحلة الأولى والجمع وPDF لا تتغير بهذه الوثيقة. المرحلة الثانية لتوسيع المصادر والمنصات تبقى في DEFERRED-SOURCE-AUTOMATION.md؛ بوت حسابات المشتركين ليس موصل جمع قنوات.

## 10. ترتيب التنفيذ المقترح ومعايير القبول

هذا ترتيب مقترح للمراجعة، وليس إذنًا ببدء البرمجة:

1. الأساس: Areas وControllers والاسم ومسارات اللغة، مع اختبار الروابط القديمة وSEO والتحويل دون حلقات أو فقد query/PathBase، ثم الأخطاء والتحميل.
2. الحسابات: بيانات العضو وربط Telegram والرموز والاستعادة والتعليق والتدقيق ومساحة المستخدم. قبول: عزل الحسابات ومنع إعادة استخدام الرمز وانتحال جهة الاتصال، واختبار استعادة وتغيير الربط.
3. الحقوق: الباقات وإصداراتها وإتاحة الأنواع والمحفوظات والتفضيلات وإدارة الاشتراكات. قبول: منع الرابط المباشر، حفظ نسخة المزايا، تمديد وتجديد وتسلسل وتجميد واستئناف مضبوط.
4. الدفع: لحظة أولًا وجوال باي عند جاهزية ملفاته؛ الخصم ومراجعة الطلب والموافقة والمهل وAPI/webhooks ومراجعات الإدارة. قبول: دفع ناجح وفاشل ومكرر ومتأخر واختلاف مبلغ واعتماد يدوي ثم تأكيد لاحق، دون منح مكرر.
5. التنبيهات: ربط حدث النشر بطابور دائم والمطابقة والأوامر وإعادة التفعيل وتذكيرات الانتهاء والمحفوظات. قبول: إعادة تشغيل واستئناف دون فقد/تكرار مقصود، وعدم إرسال فرصة لم تعد صالحة أو دون حق وقت الإرسال.
6. تجربة محلية ثم بيئة استضافة تجريبية: AR/EN والهاتف والفلاتر والترقيم، webhook HTTPS وإعادة تشغيل العامل وأمان المرفقات ومراقبة الفشل. الدفع الفعلي يتطلب تفويضًا وتجربة محدودة؛ اختبار الاستضافة السابق ما زال مؤجلًا.

## 11. المطلوب لاحقًا من صاحب المشروع وما يحتاج حسمًا

- ملفات تكامل لحظة وجوال باي وعقودهما الرسمية وبيئة الاختبار وحالات API والتوقيع. تقديم المفاتيح عبر إعدادات آمنة لا داخل هذه الوثيقة أو المحادثة أو Git.
- إنشاء البوت وتوفير إعداداته سرًا، واختيار webhook أو polling مناسب للاستضافة ومسار HTTPS إن استُخدم webhook.
- الاسم الإنجليزي، محتوى الشروط والخصوصية وعدم الاسترداد، سياسات الاحتفاظ بالأدلة وطلبات المراجعة، وطريقة تحقق الإدارة من الهوية.
- معالجة دفعتين ناجحتين لمحاولتين للشراء نفسه، وحدود الطلبات والأكواد، والتواريخ الحدية للتذكيرات عند الاشتراكات المتتابعة. هذه نقاط تصميم/قرارات متبقية، لا مزايا نعد بأنها نُفذت.
- لا حاجة لإرسال مفاتيح الآن؛ المرحلة الحالية توثيق ومقارنة فقط.
