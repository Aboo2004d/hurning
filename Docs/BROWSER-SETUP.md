# إعداد Chromium من ملف الإعدادات

المسار السابق في start-local.ps1 كان `.playwright-browsers` داخل جذر المشروع. بقي هذا المجلد مكان ملفات المتصفح المحلية، وأصبح كل من Web وWorker يقرأ إعداداته من appsettings.json:

```json
"Browser": {
    "BrowsersPath": ".playwright-browsers"
}
```

عند البناء والنشر تنسخ `Directory.Build.targets` مجلد المتصفحات من جذر المشروع إلى `.playwright-browsers` بجانب ملفات تشغيل Web وWorker، مع حفظ مجلدات الإصدارات وملفات Chromium وheadless shell وffmpeg والتراخيص. لا تُنسخ بيانات `.links` الخاصة بمتابعة تثبيت Playwright المحلي. لا تُرفع الملفات الكبيرة إلى Git؛ المجلد مستثنى كما كان. يجب وجود الملفات على جهاز البناء كي تدخل حزمة النشر، والبناء لا ينزّلها تلقائيًا. حزمة Windows لا تعمل على Linux والعكس.

أزيل تحديد مسار Chromium وفحص المجلد الثابت من start-local.ps1، وأزيل BrowserDirectory ومتغير المتصفح من install-worker.ps1. لا يحتاج المستخدم ضبط Environment أو Secrets لمسار المتصفح. داخليًا يترجم البرنامج قيمة JSON إلى متغير العملية الذي يتطلبه محرك Playwright قبل إنشائه، دون تعديل متغيرات الجهاز أو Registry.

كل مسار نسبي يُحسب من AppContext.BaseDirectory، وليس مجلد PowerShell أو contentRoot الخاص بـIIS. لا يتطلب اسم إصدار مثل chromium-1234 داخل JSON؛ Playwright يختار الإصدار الموافق له. إعادة تشغيل الموقع والعامل مطلوبة بعد تغيير الإعدادات.

## تثبيت أولي أو تحديث إصدار المتصفح

إذا كانت `.playwright-browsers` موجودة بجذر المشروع من الإعداد السابق، ابنِ المشروع كالمعتاد، ولا تنقلها يدويًا. عند تثبيت جديد بالإعداد النسبي المرفق:

```powershell
dotnet run --project src/HiringPs.Worker -c Release -- --install-browser
Copy-Item -LiteralPath '.\src\HiringPs.Worker\bin\Release\net10.0\.playwright-browsers' -Destination '.' -Recurse -Force
.\scripts\start-local.ps1
```

أمر التثبيت يقرأ appsettings الخاص بالعامل ويثبت في المجلد المضبوط بجانب تشغيله. النسخ إلى الجذر يجعل البناء اللاحق يرفقه بالويب والعامل معًا. عند تحديث Playwright ثبّت متصفحه الموافق مجددًا. لا يلزم هذا النسخ عند استعمال مسار كامل مشترك.

## الاستضافة

ارفع مخرجات النشر كاملة مع مجلدها `.playwright-browsers`. إذا كانت الأدوات مناسبة لنظام ومعمارية السيرفر، لا تعدل الإعداد النسبي. امنح حساب Web وحساب Worker قراءة ملفات المتصفح وتشغيلها والوصول إلى temp الخاص بهما.

يمكن بدل نسختين استخدام مجلد مثبت مشترك، بكتابة `Browser:BrowsersPath` كاملًا في ملف إعدادات كل تطبيق، ثم تشغيل `HiringPs.Worker.exe --install-browser` مرة واحدة على السيرفر. هذا هو مسار تخزين Playwright، وليس مسار chrome.exe.

إذا أردت متصفحًا مثبتًا منفصلًا، يمكن ضبط `Browser:ExecutablePath` إلى ملفه، مطلقًا أو نسبيًا من مجلد التشغيل، أو استخدام Browser:Channel بالطريقة السابقة. يظل توافق المتصفح مع Playwright ومسؤولية تثبيته مطلوبين. إذا لم يكن أي مسار مضبوطًا، تبقى آلية Playwright الافتراضية مدعومة.

تظهر مشاكل التثبيت والصلاحيات من صفحة الأدوات، ومن مساعد إعداد المصدر بحساب Web. بيانات SQL وAI وبقية إعدادات تشغيل السكربتات لم تتغير في هذا التعديل.

## Edge ثم Chromium

الجمع وفحص المتصفح يستخدمان مسار الإطلاق نفسه: محاولة تشغيل Edge المثبت
(`msedge`) أولًا، ثم Chromium المتوافق مع إصدار Playwright من مجلد المتصفحات
إذا فشل إطلاق Edge. لا يتم تنزيل متصفح أثناء الطلب ولا تُعاد عملية الجمع بسبب
فشل صفحة بعد تشغيل المتصفح. يجب إبقاء ملفات Chromium وتوابعها في حزمة النشر
ليعمل البديل عند غياب Edge. إعداد `Browser:Channel` القديم لا يفرض متصفحًا بعد
هذا التغيير. المسار الصريح `Browser:ExecutablePath` يتجاوز الاختيار التلقائي
للبيئات المخصصة؛ اتركه فارغًا لاستخدام Edge ثم Chromium.
