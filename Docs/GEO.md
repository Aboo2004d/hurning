# GEO — تحسين فهم الموقع لدى محركات الإجابة

المقصود هنا Generative Engine Optimization، وليس ترميز موقع جغرافي أو إحداثيات.

## التنفيذ

- صفحة «من نحن» تعرض تعريفًا صريحًا بدور الموقع وحدود الاستخراج والتقديم، مع
  أسئلة وأجوبة واضحة بالعربية والإنجليزية. محتوى الأدمن القابل للتحرير يبقى محفوظًا.
- النص المرئي وبيانات FAQPage يستندان إلى مصدر بيانات واحد لتفادي اختلاف الإجابات.
- لا يُنسب الإعلان إلى فرص فلسطين كجهة توظيف، ولا تُختلق عناوين أو رواتب أو مواعيد.
- ملف `/llms.txt` يعرّف الهوية ويربط بالصفحات العامة والأنواع وخريطة الموقع،
  ويشرح الفرق بين تاريخ التحقق والنشر، وحدود غياب الموعد، ودور المصدر الأصلي.
- لا يتضمن الملف محتوى الإدارة أو رسائل التواصل أو أسرار الإعدادات.
- يعتمد الملف والبيانات المنظمة على `Seo__PublicOrigin` نفسه المستخدم في SEO.

## الحدود

`llms.txt` صيغة مقترحة اختيارية وليست معيارًا ملزمًا تدعمه كل محركات الإجابة.
لا تضمن الظهور أو الاستشهاد أو ترتيب الإجابات، ولا تغيّر صلاحيات الوصول أو سياسات
التدريب. كذلك وجود FAQPage لا يضمن نتيجة غنية في Google؛ أهلية عرض تلك النتائج محدودة.
النص الواضح المتاح للزحف، والروابط للمصادر، وصحة المعلومات أهم من الملف وحده.

لا نضيف JobPosting لوصف مختصر، أو تقييمات مختلقة، أو بيانات اتصال غير موثقة.
لا يلزم مفتاح API أو خدمة مدفوعة لهذه التهيئة.

## بعد النشر

تحقق من `/llms.txt` وصفحة «من نحن» باللغتين، ومن تطابق الأسئلة المرئية والبيانات
المنظمة في مصدر الصفحة. تحقق من الروابط الأساسية وملفات sitemap وإمكانية الزحف.
راقب لاحقًا الإشارات والاستشهادات الفعلية؛ لا تُوصف تهيئة تقنية بأنها ظهور مؤكد
في ChatGPT أو Gemini أو Copilot أو غيرها دون دليل مستقل.
