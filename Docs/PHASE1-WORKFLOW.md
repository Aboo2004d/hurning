# استكمال المرحلة الأولى — 16 أكتوبر 2026

هذا الملف يوضح التعديلات التي اعتمدها المستخدم، وحدود التحقق منها. تفاصيل البنية القديمة وفحوص المصادر بتاريخ 11–12 أكتوبر تبقى سجلًا تاريخيًا، وليست وصفًا لإعدادات المصادر الحالية.

## القرارات المعتمدة

- الاسم التجاري «فرص فلسطين» معتمد. نموذج AI جُرّب واختير بالفعل بحسب تأكيد المستخدم؛ لا يلزم اختيار جديد.
- حد الملخص توجيه للـAI فقط، وليس قيدًا على قاعدة البيانات أو مانعًا للحفظ اليدوي والنشر.
- المرحلة الأولى تستخدم خمسة مصادر اختبرها المستخدم وقبل نتائجها. المهاجرة لا تضيف مصادر ولا تغيّر تفعيلها أو إعداداتها.
- كلمة مرور الأدمن غُيّرت من اللوحة بحسب تأكيد المستخدم؛ لا يعيد السيدر تعيينها.
- اختبار الاستضافة مؤجل. نُفّذ تطوير PDF/OCR لاحقًا بتكليف المستخدم في اليوم نفسه؛ المتطلبات والاختبارات في [PDF-TEXT.md](PDF-TEXT.md).

## استكمال الجمع بعد التوقف

يحفظ `DiscoveryCheckpoints` رابط الصفحة التالية، وعدد الصفحات المحفوظة، وروابط الصفحات السابقة، وعدد نقرات الترقيم عند استخدام JavaScript. تحفظ عناصر الصفحة ونقطة التقدم في معاملة SQL واحدة، قبل الانتقال إلى الصفحة التالية. تعرض لوحة المصادر تقدم الاكتشاف غير المكتمل.

عند إعادة التشغيل يستأنف العامل من النقطة المحفوظة. إذا كان الترقيم يعتمد على JavaScript يعيد النقرات اللازمة للوصول إلى موضع الاستكمال. الخلاصات والموصلات ذات الاستجابة الواحدة تحفظ دفعة ذرية واحدة. تبقى معالجة المحتوى وAI في طابور SQL مستقل؛ فشل AI لا يفقد الروابط المكتشفة.

تغيير إعداد المصدر يبدأ اكتشافًا جديدًا مع الإبقاء على العناصر المعروفة ومنع تكرارها. بلوغ حد الصفحات أو تعذر زر الترقيم لا يُسجّل نجاحًا زائفًا؛ تبقى نقطة التقدم لإعادة المحاولة بعد معالجة السبب. تغيير الصفحة أو ترتيب نتائج المصدر أثناء الانقطاع قد يتطلب جولة لاحقة لالتقاط إعلانات أضيفت قبل نقطة الاستكمال.

يبقى منع التداخل بقفل SQL من نوع `sp_getapplock` مرتبط بجلسة العامل؛ لا يُستبدل بـlease. لا توجد معاملة SQL مفتوحة أثناء انتظار الموقع أو AI.

## البرومبت المتغير مع حفظ النسخ

تضيف المهاجرة `PhaseOneWorkflow` نسخة رقم 1 إلى `PromptVersions`، تتضمن:

- `LegacySnapshot`: النص الكامل السابق حرفيًا قبل هذه الدفعة.
- `Template`: النص القابل للتحرير مع المتغيرات.
- شروط النسخة: طول الملخص، النطاق داخل فلسطين، الأنواع المسموحة، والسماح بانتهاء غير محدد.
- `DateContract`: تعليمات استخراج التواريخ بأدوارها.
- `FinalText`: النص النهائي الذي سيرسل للنموذج، محفوظ كما هو لهذه النسخة.

لوحة التحكم ← تعليمات النموذج: غيّر الشروط أو النص المتقدم، ثم عاين النص واحفظ نسخة جديدة. المتغيرات المتاحة: `{{summaryLimit}}`، `{{scope}}`، `{{allowedKinds}}`، `{{allowUnknownDeadline}}`. قواعد مطابقة الأدلة والنطاق الفلسطيني تبقى مفحوصة في الكود، ولا يكفي تعديل النص لتجاوزها.

الحفظ لا يستبدل نسخة قديمة؛ ينشئ نسخة معلّقة. يفعّل العامل أحدث نسخة معلّقة عند بداية الجولة التالية تحت قفل الجمع. يعيد جدولة العناصر غير المنشورة وغير المؤرشفة من المصادر المفعّلة والمعتمدة، مع حماية القرارات اليدوية. العناصر ذات المحتوى المحفوظ تعود إلى انتظار AI؛ والتي لم يجلب محتواها تعود إلى انتظار الجلب. يكرر العامل مطابقة إصدار الطابور بعد إعادة التشغيل لضمان استكمال الجدولة إذا توقف أثناء تفعيل النسخة.

النتائج المنشورة والمؤرشفة سابقًا تبقى كما هي عند تغيير النسخة. إذا احتوى الإعلان الخام على نتائج مختلطة، تعالج النتائج المؤهلة فقط وتحمى النتائج القديمة. التحديث العادي للمصدر في النسخة نفسها مسار مستقل عن إعادة المعالجة بسبب تغيير البرومبت. إعادة نسخة قديمة تتم بفتحها وحفظ نسخة جديدة، مع سجل تدقيق.

## التواريخ والأدلة

يفصل الاستخراج بين تاريخ النشر، وتاريخ التعديل، وموعد انتهاء التقديم، وشراء الكراسة، وزيارة الموقع، وفتح المظاريف، وأحداث أخرى ذات تسمية صريحة. كل تاريخ له قيمة رقمية واقتباس أصلي يوضح دوره.

قبل الحفظ يتحقق الكود من وجود الاقتباس في النص، وتطابق التاريخ الرقمي معه، ووجود تسمية مناسبة للدور. لا يصبح تاريخ النشر أو فتح المظاريف موعد انتهاء للتقديم. يرفض تاريخ نشر/تعديل مستقبلي غير منطقي، وتعارض قيم النوع الأساسي نفسه، وانتهاء التقديم قبل النشر. أسماء الأشهر العربية والإنجليزية تُطابق دون تغيير اقتباس الدليل.

لا يستبدل موعد موثوق مختلف بموعد آخر إلا إذا كان تمديدًا لاحقًا وله نص تمديد صريح. غياب الموعد وحده مسموح افتراضيًا، وفق القرار السابق؛ يمكن تغيير الشرط في نسخة جديدة. الغموض والتعارض يذهبان للمراجعة دون الكتابة فوق موعد موثوق.

صفحة عنصر المصدر في الإدارة تعرض القيم المقترحة واقتباساتها حتى عند رفض التحقق؛ وصفحة تفاصيل الفرصة تعرض التواريخ المؤكدة وأدلتها. تاريخ الإضافة للموقع مستقل عن تاريخ النشر لدى المصدر. تحفظ سجلات التواريخ التاريخية مع إصدار البرومبت ومعرّف المصدر. هذا تحقق للنص الذي وصل بالفعل. استُكمل لاحقًا مسار PDF وOCR الموثق في [PDF-TEXT.md](PDF-TEXT.md)، مع مراجعة بصرية افتراضية للنص الذي قرأه OCR.

## البحث والدمج وسجل AI

- البحث يطبع الهمزات والتشكيل والمسافات في حقول بحث منفصلة، ويدعم أسماء عربية/إنجليزية بديلة للمواقع الأساسية، مثل رام الله/Ramallah وأريحا/Jericho. النص الأصلي المعروض لا يتغير. يمكن توسيع القاموس في `LocationSearch.cs`.
- الدمج الجديد يحفظ الحالة السابقة، وقرارات التدخل اليدوي، وروابط المصدر المنقولة، ونسخ التزامن. يمكن التراجع من «سجل الدمج» إذا لم تتغير السجلات بعد الدمج. عند وجود تعديل لاحق يمنع التراجع حتى لا يمحوه. يتيح فك سلسلة دمجات بالترتيب العكسي. الدمجات القديمة التي لم تحفظ لقطة لا يمكن اختلاق استعادة لها.
- «استخدام الذكاء الاصطناعي» يعرض المحاولات الناجحة والفاشلة وغير المكتملة، والموديل، وإصدار البرومبت، والمدة، وحالة HTTP، والتوكنز التي أبلغ عنها المزود. القيم غير المتاحة تبقى مجهولة؛ لا تقدّر تكاليف أو توكنز. قد تظهر محاولة غير مكتملة إذا انقطع العامل قبل تسجيل النتيجة. لا تحفظ مفاتيح API أو جسم استجابة الخطأ في هذا السجل.

## الاحتفاظ بالسجلات

من «الاحتفاظ بالسجلات» يمكن تعديل مدة نسخ المحتوى السابقة وملفات التشخيص أو تعطيل التنظيف. الافتراضي 90 يومًا لنسخ المحتوى و30 يومًا للتشخيص، وينفذ العامل التنظيف مرة يوميًا. الملفات المستهدفة فقط ملفات التشخيص المنشأة بمعرّف GUID وامتداد json/jpg، وبحد 200 ملف في الجولة. لا يحذف الفرص أو المحتوى الحالي أو روابط المصادر أو سجلات الأدمن أو نسخ البرومبت أو إحصاءات AI.

## المهاجرة والتحقق

قبل تحديث بيئة فعلية: نسخة احتياطية، ثم نافذة تحديث مناسبة مع إيقاف العامل أثناء ترقية المخطط. الموقع يحتفظ بمسار تطبيق المهاجرات الحالي عند البدء. المهاجرة تضيف الحقول والجداول وتجهز حقول البحث للبيانات القديمة، دون إعادة إنشاء قاعدة البيانات. SQL Server 2017 أو أحدث مطلوب لدوال البحث المستخدمة في الترحيل.

فحوص لا تحتاج SQL أو طلبات خارجية:

```bash
dotnet build HiringPs.sln -c Release
dotnet run --project tests/HiringPs.Checks -c Release -- --workflow-check
```

اختبارات SQL الإضافية:

```bash
dotnet run --project tests/HiringPs.Checks -c Release -- --workflow-sql-check
```

تحتاج الأخيرة متغير `HIRING_TEST_SQL` لاتصال SQL Server اختباري مع صلاحية إنشاء وحذف قاعدة اختبار. يُضبط خارج المستودع ولا تُرسل قيمته في المحادثة. تنشئ قاعدة باسم عشوائي يبدأ بـ`HiringPs_WorkflowChecks_`، تطبق المهاجرات وتختبر إعادة الجدولة وحماية النتائج والدمج والتراجع والتنظيف وانقطاع الجمع والاستكمال وتسجيل الاستخدام، ثم تحذف قاعدة الاختبار فقط. لا تستخدم اتصال الإنتاج لهذا الغرض.

التحقق المتاح هنا: نجح بناء الحل و39 فحصًا مستقلًا. اختبار SQL الفعلي واختبار الواجهات المتصلة بقاعدة البيانات غير منفذين هنا لعدم توفر اتصال SQL اختباري. نجاح البناء والفحوص المستقلة لا يثبت تشغيل هذه السيناريوهات على الاستضافة.

## فهم موعد النهاية من السياق

الموديل يصنف موعد نهاية التقديم أو التسجيل أو تسليم العروض دلاليًا، دون اشتراط كلمات مثل «آخر موعد». تتضمن التعليمات عدم استخدام نهاية الوظيفة أو التدريب أو المشروع أو العقد، أو تاريخ النشر أو التعديل أو بدء التسجيل كموعد إغلاق. يحتفظ التحقق بشرط وجود الاقتباس في المصدر ومطابقة قيمة التاريخ، ويرفض التصنيف عند وجود نوع حدث آخر صريح في اقتباس الدليل. يجب أن يكون الاقتباس فقرة قصيرة تخص الحدث نفسه؛ لا تجمع عدة أحداث متباعدة. غموض الحدث أو السنة يحتاج مراجعة؛ غياب الموعد وحده يتبع شرط السماح المعتمد.

المهاجرة `SemanticDeadlinePrompt` تنسخ البرومبت المنتظر إن وُجد وإلا الفعّال، وتحفظ الشروط والتخصيصات والنص السابق، وتضيف التعليمات كنسخة جديدة منتظرة. العامل يفعّلها في بداية الجولة التالية ويعيد معالجة غير المنشور وغير المؤرشف وفق الحماية الحالية لقرارات الأدمن. لا تُعدّل نسخة البداية التاريخية، ولا تُعاد كتابة البرومبتات السابقة. أي نسخة جديدة تحفظ من اللوحة تتضمن سياسة التاريخ الحالية. التراجع عن المهاجرة لا يحذف سجل البرومبت؛ للاستعادة افتح نسخة سابقة واحفظها كنسخة جديدة.
