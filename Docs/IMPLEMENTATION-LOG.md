# سجل التنفيذ

## 18 أكتوبر 2026 — العضوية والباقات وتليجرام

- تنفيذ مناطق الإدارة والمستخدم وفصل Controllers القديمة والجديدة حسب المسؤولية مع حفظ الروابط السابقة.
- بادئات اللغة AR/EN، الاسم الجديد، أخطاء وهوية التحميل، وتحديث SEO للمناطق الخاصة.
- حسابات وتحقق بوت واستعادة وربط وتغيير تليجرام، وتفضيلات ومحفوظات.
- إصدارات باقات وحقوق تفاصيل وتنبيهات مستقلة، وتسلسل الاشتراكات والتجميد والتدقيق والخصومات.
- طلبات دفع ومراجعات وأدلة خاصة واعتماد يدوي وتحقيق حالة الطلب من الموقع والبوت، مع منع المنح المتكرر.
- worker للبوت وطابور الرسائل والتذكيرات ومراقبة التسليم. إعدادات *** في ملفات المشروع.
- migration جديدة مع حماية البيانات التاريخية من تنبيهات جماعية، وتوليد مخطط SQL دون تطبيقه هنا.

التحصيل الخارجي غير مكتمل لغياب عقود API/ملفات تكامل لحظة وجوال باي؛ البوابات مخفية للمستخدم حتى اكتمال adapter صحيح واختباره. لم يُستخدم مفتاح حقيقي أو دفع أو بوت أو SQL حي. تفاصيل التشغيل وحدود الاختبارات في [MEMBERSHIP-SETUP.md](MEMBERSHIP-SETUP.md).

سجل التنفيذ السابق موزع في الوثائق الحالية، خصوصًا PHASE1-WORKFLOW وPDF-TEXT وBROWSER-SETUP وSOURCE-SETUP؛ لا يمثل إنشاء هذا الملف إعادة بناء لسجل commits قديم.

## 18 أكتوبر 2026 — جوال باي وSandbox وفحوص بوابات الدفع

- وصل عقد الشريك للـinitiate/confirm/balance/transactions ثم Sandbox. أضيف موصل C# فعلي من السيرفر مع X-Partner-Key والمبلغ بالشيكل وحدوده 1–5000.
- إضافة جلسة SQL مشفرة وبصمة فريدة، ومحاولة confirm محجوزة قبل الاتصال ولا تتكرر حتى بعد 422 أو timeout؛ الرمز لا يُحفظ. الإيصال والرسوم منفصلان عن المبلغ الإجمالي، والاستكمال GET من آخر 50 عملية لا يعيد الخصم ولا يعتبر الغياب فشلًا.
- التشغيل Development يستخدم Sandbox لجوال باي ولحظة؛ Production يستخدم مفاتيح ومسارات الإنتاج. بيانات الهاتف والرمز تظهر على شاشة التطوير فقط. الطلبات وفترات الاشتراك موسومة بالبيئة لمنع منح مزايا Sandbox في الإنتاج.
- إضافة بطاقتي لحظة وجوال باي لفحص الأدوات اليدوي/منتصف الليل عبر GET فقط. لا SMS أو دفع في الفحوص.
- إضافة فحوص HTTP محاكاة وفحوص SQL اختيارية للتزامن والاستكمال بعد reset وعزل البيئات، وتوثيق التشغيل المحلي والاستضافة في PAYMENT-ENVIRONMENTS.md وJAWWAL-PAY.md. بقيت المفاتيح *** ولم تُجر معاملة خارجية حقيقية.

التحقق النهائي: نجاح بناء الحل و206 فحوص محلية و24 حالة عرض Chromium للبيئتين واللغتين، وتوليد SQL للمخطط. فحوص SQL الحية وتكامل Sandbox الحقيقي لم تُنفذ دون اتصال الاختبار والمفاتيح. أوقفت مضيفات المعاينة التي أنشأتها.


## 18 أكتوبر 2026 — إصلاح سعر الباقة وفصل نماذج الإضافة والتعديل

- سبب خطأ 500 في إضافة الباقات: `RangeAttribute` كان يحوّل الحد `0.01` باستخدام ثقافة الجهاز؛ تنسيق الأرقام العربي في Windows قد يرفض النقطة. أصبحت حدود decimal ثابتة الثقافة، وحقل السعر يرسل ويقرأ الفاصل العشري وفق HTML number دون تغيير لغة الواجهة.
- فصل `Create` و`Edit` (GET/POST) في كنترولرات الباقات والخصومات والمصادر والفرص، مع إبقاء الحفظ والتحقق المشترك في دوال خاصة. الإضافة ترفض معرّف سجل قائم والتعديل يطابق معرّف الرابط بالنموذج.
- القوالب المشتركة: `PlanForm`, `DiscountForm`, `SourceForm`, `OpportunityForm`. روابط الإضافة تتجه إلى Create، ونماذج التعديل إلى Edit مع المعرّف. روابط Edit القديمة دون معرّف وروابط Source القديمة تحوّل إلى المسار المناسب.
- مسارات النماذج الصريحة تسبق مسارات الإدارة القديمة لمنع تفسير Create/Edit كمعرّف مصدر أو فرصة. تبقى الأذونات وCSRF وفحص النسخ والتزامن ونسخ الباقات محفوظة.
- لا تغيير على مخطط قاعدة البيانات أو إعدادات الدفع أو تليجرام في هذه الدفعة.
- التحقق: نجح بناء Web/Core ومشروع الفحوص و200 فحص محلي، تشمل محاكاة فواصل Windows العربية، قراءة السعر العشري وحدوده، عرض قوالب التعديل الأربعة، مسارات Create/Edit ومنع اختلاف المعرّفات. لم تُنفّذ عمليات حفظ على SQL حي في البيئة السحابية. تحذيرات حزمة Pkcs الموجودة سابقًا ما زالت تظهر.


## 18 أكتوبر 2026 — قبول رد لحظة دون domain

- أظهر رد verify الفعلي نجاح الدفعة ومرجعها ومبلغ 500 أغورة وعملة ILS دون قيمة domain. اشتراط هذا الحقل في الرد كان يعيد GatewayUnavailable ويترك الطلب معلقًا رغم نجاح الدفع.
- أصبح domain اختياريًا عند غيابه أو null أو النص الفارغ؛ القيمة غير النصية أو النص الصريح المخالف للبيئة يظل مرفوضًا. ما زال الاتصال الموثق بمفتاح البيئة المحددة، وتطابق الطلب والمرجع والمبلغ والعملة وstatus=success شروطًا لتفعيل الاشتراك. لا تغيير على حماية Webhook.
- لا يحتاج الإصلاح Migration أو دفعًا جديدًا؛ يمكن إعادة التحقق من الطلب القديم بعد إعادة التشغيل.
- التحقق: نجح بناء Web/Core ومشروع الفحوص و42 فحص لحظة بمحاكاة API، بما يشمل غياب/null/فراغ domain ومفاتيح Test/Live ورفض البيئة الصريحة المخالفة والمبلغ أو العملة أو المرجع غير المطابق. لم تُجر مكالمة بمفتاح المستخدم أو اعتماد دفع حي من البيئة السحابية.


## 18 أكتوبر 2026 — تتبع تحقق الدفع وتنسيق الأزرار

- أضيف PaymentTrace لكل محاولة تحقق، مع مراحل الإعداد وطلب المزود وتفسير الرد واعتماد الاشتراك، ورموز فشل ثابتة وحالة HTTP. يحفظ ملخصًا محدودًا في Audit عبر سياق مستقل ويكتب مراحل التنفيذ في سجلات Web/Worker، دون تسجيل الأسرار أو أجسام الردود أو رسائل الاستثناء.
- تعرض تفاصيل دفع الأدمن آخر 10 محاولات وإصدار التتبع، ويرى العضو رقم تتبع فقط. فشل حفظ التشخيص لا يفشل الدفع؛ لا يلزم Migration.
- أضيفت رسائل PaymentWebhook الآمنة لتشخيص الإعداد والتوقيع وعدد الطلبات المطابقة. التحقق اليدوي يبقى مستقلًا عن Webhook.
- أزرار فحص الدفع وإتمامه وإعادة المحاولة أصبحت ضمن مجموعة متناسقة متجاوبة تستخدم تنسيق الموقع. لا تعرض للطلب المدفوع دعوة دفع جديدة أو نموذج «تم الخصم ولم يتفعّل اشتراكي» جديدًا.
- الخطوات والتفسير في PAYMENT-DIAGNOSTICS.md.
- التحقق: نجح بناء الحل ومشروع الفحوص و311 فحصًا محليًا (تشمل لحظة وجوال باي والعضوية)، و8 حالات عرض في Chromium بالعربية والإنجليزية على 390 و1440 بكسل دون خروج أفقي. لم تُختبر كتابة Audit على SQL حي أو دفعة المستخدم أو Webhook حي هنا؛ يجب إعادة فحص الطلب نفسه على جهاز المستخدم بعد تحديث المشروعين.


## 18 أكتوبر 2026 — قراءة أنواع حقول تحقق لحظة

- أثبت التتبع من Web وWorker جهوزية Sandbox وHTTP 200، ثم فشل قراءة رد المزود (`MalformedVerificationData`). لا يشير ذلك إلى خلل Webhook؛ الاستعلام اليدوي مستقل عنه. لا يحدد السجل القديم وحده الحقل أو نوعه.
- أصبح مبلغ الأغورات يقبل JSON number أو نصًا رقميًا ثابت الثقافة مثل `"500"`؛ لا تُقبل فواصل التجميع أو وحدات العملة أو الأسس داخل النص أو أجزاء الأغورة أو القيم السالبة. لا تزال مطابقة المبلغ والمرجع والعملة وحالة النجاح والبيئة المصرح بها إلزامية.
- أضيفت رموز حقلية مثل `AmountInvalidString`, `ReferenceMissing`, `CurrencyTypeNull`, `StatusTypeTrue` بدل إخفاء كل أخطاء القراءة تحت سبب واحد. لا تُسجل قيمة الحقل أو جسم الرد.
- إصدار التتبع الجديد `payment-trace-typed-fields-v2`. لا يلزم دفع جديد أو Migration.
- التحقق: نجح بناء الحل ومشروع الفحوص و72 فحص لحظة وتتبع بمحاكاة API، منها المبلغ الرقمي والنصي، المبالغ غير المطابقة أو المعيبة، والحقول الناقصة أو ذات النوع غير الصحيح. لم يُحسم نوع الحقل في الرد الحي لأن جلسة PowerShell السابقة أُغلقت؛ لم تُعد معاينة دفعة المستخدم من البيئة السحابية.


## 18 أكتوبر 2026 — تتبع إرسال رمز وتأكيد جوال باي

- السجل السابق كان لفحص الحالة فقط؛ Pending في Sandbox لا يثبت وصول confirm أو نجاحه. أضيف تتبع كامل لمساري Initiate وConfirm: بدء الطلب، حفظ claim، إرسال الطلب، قراءة الرد، حفظ الإيصال، وتفعيل الاشتراك. يبقى رمز OTP ومفتاح الجلسة ورقم الهاتف خارج السجلات.
- أضيفت أكواد HTTP وفشل قراءة حقل محدد في موصل جوال باي. الحقول الرقمية في الإيصال وتهيئة الجلسة تقبل رقم JSON أو نصًا رقميًا ثابت الثقافة، مع بقاء مطابقة المبلغ والمرجع إن وجد ومعرّف العملية والرسوم والصافي إلزامية. المراجع nullable في رد confirm المباشر يمكن غيابها، لكن external_ref في قائمة العمليات ما زال إلزاميًا ومطابقًا.
- يوضح الفحص التجريبي `WalletSandboxReceiptMissing` أو `WalletAwaitingOtpConfirmation` بدل Pending وحدها. لا توجد إعادة confirm أو تصفير للحجز أو استعمال قائمة الإنتاج لجلسة اختبار. الجلسة القديمة غير المحفوظ ردها لا يمكن استعادتها بهذا التعديل.
- إصدار التتبع `payment-trace-wallet-confirm-v3`؛ لا تغيير على مخطط SQL.
- التحقق: نجح بناء الحل ومشروع الفحوص و341 فحصًا محليًا (64 جوال باي، 72 لحظة/تتبع، 205 عضوية وواجهات). HTTP محاكى، ولم تتوفر SQL حية لاختبار حجز التأكيد وكتابة الإيصال أو تنفيذ Sandbox خارجي؛ اختبارات SQL الاختيارية تبقى غير منفذة هنا.
