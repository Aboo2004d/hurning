# سجل العمليات وقوالب التليجرام

## الوصول والاستخدام

- **النظام وAI ← سجل العمليات**: `/ar/Admin/Operations` (أو `/en/Admin/Operations`). للمسؤول فقط، دون تخزين مؤقت للاستجابة.
- البحث في العملية والتفاصيل والمنفذ، والفلترة بالمجال والنتيجة والمنفذ واليوم الفلسطيني، مع ترقيم الصفحات في SQL والحفاظ على المرشحات عند التنقل. تاريخ النهاية يشمل اليوم كاملًا.
- **المحتوى والتواصل ← قوالب النشر**: اختيار «قوالب قنوات التليجرام» أو «قوالب تنبيهات البوت»، ثم القالب العام أو نوع الفرصة. الحفظ ينشئ إصدارًا ثابتًا؛ الاسترجاع ينشئ إصدارًا جديدًا ويحتفظ بالتاريخ ويحمي من تعديلين متنافسين.
- لقنوات التليجرام مزود القالب الموجود `Telegram`؛ للبوت مزود مستقل `TelegramBot`. لا يتغير قالب فيسبوك أو لينكدإن عند تعديل أي منهما.
- تنبيهات البوت وتذكيرات الفرص المحفوظة تستخدم القالب النشط للنوع ثم العام. عند عدم اعتماد قالب، يبقى العنوان والرابط كما في السلوك السابق. رسائل الدفع والتحقق وأوامر الحساب لا تستخدم قالب الفرص.
- رابط الفرصة يضاف دائمًا خارج النص القابل للتحرير. البوت يرسل نصًا عاديًا محدودًا بـ4000 محرف توافقًا مع تخزين الرسالة؛ القنوات تحتفظ بمعالجة HTML الآمنة وحد Telegram. معاينة القناة تراعي الملخص المحدود وإتاحة صفحة التفاصيل العامة، وتستخدم رابط القائمة عندما تكون التفاصيل مقيدة.

## نطاق السجل

يظهر سجل التدقيق الإداري السابق مع أحداث التشغيل الجديدة، ولا تعاد صناعة أحداث قديمة لم تسجل أصلًا. تشمل الأحداث الجديدة:

- إضافة المصادر والفرص وحذفها وتغير حالة الفرصة، إلى جانب التدقيق الإداري الموجود لتعديلاتها.
- بدء جولة جمع لكل مصدر ثم نتيجتها وعداداتها، وعناصر المصدر التي تحتاج مراجعة أو إعادة محاولة.
- حجز النشر ونتيجته ومحاولات قنوات التليجرام، مع تمييز النتيجة غير المحسومة عن النجاح والفشل.
- إدراج رسائل البوت وتسليمها وفشلها وإلغاؤها. تحفظ كل محاولة فاشلة لاحقة كحدث مستقل عندما يتغير موعد إعادة المحاولة، حتى إذا بقي رمز الخطأ نفسه.
- استقبال تحديثات التليجرام ومعالجتها وفشل المعالجة، وحالات الدفع، واستدعاءات AI ونتائج فحوص الأدوات.
- فشل دورات الجمع والتوزيع وخدمات الأعضاء في نطاق مستقل دون حفظ تغييرات جزئية من النطاق الفاشل.

`OperationTracking.Stage` يجهز أحداث `AuditEntry` قبل `SaveChanges` المتزامن وغير المتزامن؛ تحفظ أحداث التغييرات المتتبعة في نفس معاملة EF. إعادة المحاولة داخل السياق تستبدل الأحداث الآلية غير المحفوظة بدل تكرارها. لا ينفذ المكون اتصالات شبكة أو حفظًا ثانيًا ولا يسجل نفسه.

تسجل أحداث الإنشاء اسم المصدر أو عنوان الفرصة قبل توليد الهوية الرقمية، بينما تتضمن أحداث الانتقال اللاحقة المعرف المحفوظ. لا تنسخ إعدادات المصادر أو نصوص المستندات أو الرسائل أو رموز الربط أو معرفات المحادثات إلى الأحداث الآلية.

التحديثات المباشرة عبر `ExecuteUpdate` لا تمر بمتتبع EF؛ عند إضافة حدث جديد في مثل هذا المسار يجب استخدام `OperationTracking.Create` صراحة. تعذر قاعدة البيانات نفسها قد يمنع حفظ حدث الفشل؛ يبقى سجل العامل الأصلي متاحًا، ولا يعيد المسجل تنفيذ العملية الخارجية.

## إصلاح فحص الأدوات

كان العرض يقارن كل النتائج بهوية آخر عامل أرسل نبضة حياة. بوجود عاملين، يكفي اختلاف العامل صاحب أحدث نبضة لعرض نتائج العامل الآخر كغير متحققة. يقرأ العرض الآن العمال المشار إليهم في النتائج دفعة واحدة، ويفحص كل نتيجة مع عاملها. يبقى انتهاء صلاحية النتيجة أو توقف عاملها سببًا صحيحًا لعرضها قديمة، دون التأثير على نتائج عامل آخر.

## التهيئة والفحوص

Migration `20261020182000_OperationHistoryIndex` يضيف فهرسًا على `Audit(At, Id)` فقط، ولا يغير البيانات أو حالات الدفع والنشر. يطبق الموقع migrations عند بدء التشغيل وفق آلية المشروع الموجودة. لا تحتاج القوالب مفاتيح جديدة أو جدولًا جديدًا.

أوامر الفحص المركزة:

```sh
dotnet run --project tests/HiringPs.Checks -- --operation-check
dotnet run --project tests/HiringPs.Checks -- --membership-preview
# Against the local preview only, with Playwright and Chromium configured:
node scripts/check-operations-ui.cjs
```

نجحت 17 حالة مركزة للسجل والقوالب ونتائج الأدوات، و65 تحققًا للواجهة الجديدة بالعربية والإنجليزية على الهاتف وسطح المكتب، إضافة إلى 134 تحقق انحدار للواجهات السابقة (199 تحققًا للمتصفح). نجحت كذلك الحزم الاثنتا عشرة السابقة: إجمالي 753 تأكيدًا في 13 حزمة. تستخدم بوابات الدفع والنشر محاكاة، ولا تنشئ دفعات أو منشورات أو رسائل حقيقية. اختبارات SQL هنا تتحقق من الترجمة وتوافق النموذج؛ اختبار SQL Server الفعلي ما زال غير متاح في البيئة كما يوضح [تقرير التحقق السابق](QUALITY-VALIDATION.md).

نجح بناء الحل ومشروع الفحوص دون أخطاء. ظهر تحذيران سابقان `CS8981` بسبب اسم migration التاريخي `start`؛ لا يتعلقان بالتعديلات الجديدة.

## إصلاح تعارض مرشح المجال مع منطقة الإدارة

كان فتح `/ar/Admin/Operations` دون فلاتر يسمح لربط MVC بقراءة قيمة المنطقة `Admin` من المسار داخل مرشح `Area`، فيرفض الصفحة كطلب غير صالح. قُيّد `OperationFilterDto` بـ`FromQuery` كي تستخدم المرشحات معاملات البحث فقط. أُعيد إنتاج الفشل على المسار الحقيقي قبل الإصلاح، ثم نجحت حالات فتح الصفحة والفلترة الصحيحة ورفض المجال غير الصالح بالعربية والإنجليزية. يوقف فاحص الاختبار التنفيذ بعد ربط المدخلات وقبل SQL، ولا يدخل ضمن تطبيق الإنتاج.

### تفاصيل فشل الأدوات

تتضمن أحداث فحص الأدوات الآن حقل التشخيص الأصلي مع معرف الطلب والعامل.
تسجل مسارات فشل اكتشاف المصدر ومعالجة العنصر (بما فيها المتصفح وPDF وAI)
سبب الاستثناء ومعرف المصدر/العنصر في حدث `Activity.Tools.Failed.Execution`
ضمن حفظ الحالة نفسه، دون إعادة تنفيذ العمل. تبقى الإلغاءات الطبيعية عند إيقاف
المضيف خارج هذا التسجيل. فشل حفظ قاعدة البيانات نفسها قد يمنع حفظ الحدث.

الرسائل محدودة بسعة الحقول الحالية (1000 لنتيجة الفحص و2000 لسجل العمليات)،
مع الاحتفاظ ببداية الرسالة ونهايتها عند الاختصار لإظهار أسباب الإطلاق ورمز خروج
العملية. تحجب كلمات المرور باستخدام سياسة الحجب القائمة. يتضمن تعذر تشغيل أدوات
PDF مسار الملف ورسالة Windows ورقم الخطأ الأصلي. لا توجد ماجريشن إضافية، ولا
تستعاد التفاصيل المفقودة من الفحوص القديمة؛ يلزم تنفيذ فحص جديد بعد نشر التعديل.
