# صفحة الأدوات في لوحة الإدارة

الحالة: أضيفت بتاريخ 16 أكتوبر 2026. افتح لوحة التحكم ← **الأدوات**، أو `/Admin/Tools`. الرابط موجود في قائمة الأدمن المكتبية وقائمة الهاتف، والصفحة عربية وإنجليزية.

## ما الذي تعرضه؟

| البطاقة | معنى الفحص |
| --- | --- |
| المجمّع والعامل | نبضة مستقلة، اسم الجهاز وحساب التشغيل، بداية آخر دورة، الانتظار والمراجعة والمصادر المفعلة، وآخر جولة مصدر |
| إعدادات AI | وجود المفتاح وصلاحية صيغة اسم الموديل **في إعداد العامل**، دون طلب شبكة أو عرض المفتاح |
| اتصال AI الفعلي | طلب مستقل إلى المزود بالموديل والبرومبت الفعّالين، مع التمييز بين الاستجابة والحصة ورفض الوصول والموديل والشبكة |
| Chromium | تشغيل المتصفح بإعدادات العامل وتنفيذ JavaScript في صفحة محلية |
| Poppler النص والرسم | تشغيل pdftotext وpdftoppm وقراءة الإصدار |
| Tesseract واللغات | تشغيل المحرك وقراءة الإصدار وفحص توفر ara وeng في tessdata المستخدم |
| مجلد PDF المؤقت | إنشاء ملف تجريبي وقراءته وحذفه بحساب العامل، دون أرشفة ملفات الإعلانات |
| PDF وOCR الفعلي | قراءة عينة صناعية مدمجة من صفحة إنجليزية نصية وصفحة عربية مصورة، والتحقق من النص، مع حذف آثار الفحص المؤقتة |

الفحص الوظيفي لـPDF يكتشف مثلًا بيانات لغة مسماة ara/eng لكنها غير قابلة للتحميل فعليًا؛ مجرد ظهور الاسم أو إصدار الأداة لا يكفي وحده. العينة لا تحتوي بيانات شخصية أو إعلانًا للنشر. هي نسخة من عينة الاختبار الصناعية الموثقة في `tests/HiringPs.Checks/Fixtures/Pdf/README.md`، ومضمّنة كـEmbeddedResource في Core لتنتقل تلقائيًا مع publish، دون الاعتماد على مجلد tests على الاستضافة.

الحالات: يعمل وقت الفحص، مشكلة، غير مُعد، الإعداد موجود والاتصال غير مثبت، معطل بالإعدادات، وغير معروف/بحاجة لفحص. تظهر النتيجة ووقتها ومدتها ومعرّف العامل المنفذ، مع تعليمات المعالجة لكل أداة. الأوقات UTC.

آخر محاولة AI تعرض أيضًا الموديل وحالة HTTP والتوكنز المبلّغ عنها ونوع الخطأ، وقد تكون معالجة إعلان أو فحص اتصال ومن تشغيل سابق. نجاح AI يعني استجابة قابلة للقراءة، وليس صحة الاستخراج أو اعتماد نشر إعلان.

## كيف أشغّل الفحص؟

1. افتح صفحة الأدوات وسجّل حالة النبضة.
2. اضغط «فحص الأدوات الآن». يحفظ الموقع طلبًا في SQL ثم يعيد الصفحة فورًا. لا يشغّل أدوات الاستضافة تحت حساب IIS.
3. العامل ينفذ الطلب في الخلفية، ويحفظ نتيجة كل أداة تدريجيًا. اضغط «تحديث النتائج» بعد قليل. لا يوجد تحديث تلقائي للمتصفح.
4. لاختبار المزود، اضغط الزر المنفصل «اختبار AI فعلي — يستهلك طلبًا». لا يجري هذا الاختبار تلقائيًا ولا ضمن الفحص العادي. يستهلك الحصة/التكلفة حسب حسابك، ويُسجل في استخدام AI مع إصدار البرومبت ودون SourceItem لأنه فحص اتصال. لا ينشئ أو ينشر فرصًا.
5. إذا العامل متوقف تبقى الطلبات Pending؛ حدّث العامل وشغّله وتحقق من اتصاله بنفس SQL المستخدمة للموقع.

يوجد فحص عادي تلقائي عند بدء مراقبة العامل، وبعده تقريبًا كل ساعة. قد يتأخر فحص بدء التشغيل بسبب طلب قائم أو مهلة منع التكرار. لا يوجد أي طلب AI تلقائي من المراقبة. يسمح الطابور بطلب عادي وآخر AI منفصلين، ويمنع تكرار النوع أثناء انتظاره/تنفيذه وخلال دقيقة من آخر طلب.

إذا توقف العامل أثناء فحص، يعالج العامل التالي حالة Running كـ«توقف التنفيذ» ويحرر خانتها. لا يعيد طلب AI المتوقف تلقائيًا، لأن المزود قد يكون احتسب الطلب قبل التوقف. يمكن طلب فحص جديد صراحةً بعد ذلك.

## لماذا لا تظهر نتيجة قديمة باللون الأخضر؟

نبضة المراقبة تُحفظ كل نحو 10 ثوان، في حلقة مستقلة عن الجمع وعن فحوص الأدوات. تصبح غير حديثة بعد 60 ثانية. انتهاء النبضة لا يثبت وحده سبب التوقف؛ قد يكون العامل متوقفًا أو SQL متعذرًا، لذا تظهر تعليمات التحقق من الخدمة والسجلات.

نتيجة الأداة لا تعتبر حالية إذا مضى عليها أكثر من ساعتين، أو تغير معرّف تشغيل العامل، أو غابت نبضته الحديثة. تبقى النتيجة التاريخية مرئية مع تنبيه؛ لا تُعرض كإثبات صحة الإعداد الحالي. تغيير الإعدادات دون إعادة التشغيل يتطلب فحصًا جديدًا؛ الصفحة ليست مراقبة مستمرة لكل عملية أو اتصال.

عند وجود أكثر من عامل نشط تظهر ملاحظة. النبضة الأحدث هي المعروضة، ومعرّف المنفذ ظاهر في كل نتيجة. نتيجة عامل آخر لا توصف بأنها فحص حديث للعامل المعروض. توحيد إعدادات نسخ العامل أو الاكتفاء بنسخة إنتاجية واحدة يسهل تفسير النتائج.

فشل آخر مصدر قد يظهر مع استمرار نبضة العامل: خدمة العامل تعمل لكن المصدر نفسه فشل. افتح «المصادر» للتفاصيل. نجاح Chromium لا يثبت صلاحية الدخول إلى Jobs.ps أو تجاوز Cloudflare أو صحة محددات أي مصدر. ملفات PDF وصور الصفحات تحذف بعد المعالجة؛ رقم صفحة الدليل يبقى مستخرجًا من النص المحفوظ، والمقارنة البصرية من الأصل لدى المصدر. لا يلزم مجلد أرشيف مشترك مع IIS. نجاح العينة الصناعية لا يضمن دقة OCR لكل ملف حقيقي.

## تحديث المحلي والاستضافة

1. أوقف العامل قبل تحديث الإصدار، وخذ نسخة احتياطية من SQL.
2. حدّث Web وWorker معًا. تتضمن الدفعة مهاجرة `ToolMonitoring` تضيف `ToolCheckRequests` و`ToolCheckResults` و`ToolWorkers` وفهارسها فقط، دون تغيير الفرص أو المصادر أو البرومبت.
3. شغّل الموقع أولًا لتطبيق المهاجرة حسب المسار التلقائي الحالي، ثم شغّل/أعد تشغيل العامل. النسخة القديمة من العامل لا ترسل النبضات أو تنفذ الطابور الجديد.
4. افتح صفحة الأدوات. توقّع نبضة حديثة ثم اكتمال الفحص التلقائي أو اطلبه يدويًا.
5. اضبط قسم Pdf في **appsettings.json الخاص بالعامل** كما في [دليل PDF](PDF-TEXT.md)، ثم أعد تشغيله. السكربت أصبح فحصًا فقط، دون متغيرات جلسة أو إعدادات Registry. لا يلزم تثبيت مكتبات Node/Python إضافية للميزة.
6. Chromium يستخدم `PLAYWRIGHT_BROWSERS_PATH` و`Browser:Channel` كما في الجمع. أضيف أيضًا `Browser:ExecutablePath` / `Browser__ExecutablePath` اختياريًا لاستخدام ملف متصفح مثبت بالفعل؛ يشترك الجمع والفحص في هذا الخيار. الأفضل إبقاء متصفح Playwright المتوافق افتراضيًا، واختبار مصادر الجمع إذا اخترت متصفحًا آخر. لا تضبط Channel ومسار ملف معًا دون حاجة.

غياب مفتاح AI أو الموديل في العامل لم يعد يوقف الخدمة كاملة: يبقى الجمع والمراقبة متاحين، وتبقى العناصر بانتظار AI دون إرسال طلب بموديل بديل مفترض. تبقى متطلبات بدء تطبيق الويب الحالية كما هي.

لا توجد صلاحيات مسؤول جديدة مطلوبة للفحص نفسه؛ يحتاج حساب العامل تنفيذ الأدوات، وقراءة tessdata، وإنشاء وحذف ملفات temp، والوصول إلى SQL. يحتاج اختبار AI الفعلي اتصال HTTPS بالمزود. الإعدادات الحساسة لا تُنسخ إلى جدول النتائج، ولا تُحفظ أجسام أخطاء المزود أو سطور الأوامر أو البيئة الكاملة. الصفحة وPOST محميان بدور Admin والتحقق العام من CSRF الحالي.

## الملفات وطريقة التنفيذ

- `ToolMonitoringModels.cs`: الطلبات والنتائج والنبضات وقواعد حداثتها.
- `ToolProbes.cs`: الفحوص المحلية الفعلية دون SQL أو طلب AI ضمن الفحص العادي.
- `ToolCheckQueue.cs`: طابور SQL وتنفيذ الفحوص وقفل مستقل وتسجيل النتائج.
- `Worker/ToolMonitor.cs`: حلقتا النبضة والمراقبة مستقلتان عن `Worker` الخاص بالجمع.
- `AdminToolsController.cs` و`Views/Admin/Tools.cshtml`: الصفحة وأزرار الطابور.

قفل الأدوات منفصل عن قفل الجمع، مع حماية منع التكرار بقفل enqueue وفهرس فريد للخانات النشطة. لا تُمسك معاملة SQL أثناء انتظار الأدوات أو AI؛ يبقى قفل جلسة مراقبة واحد لمنع تنفيذ الطابور بالتوازي. الجداول تحتفظ بتاريخ الفحوص والنبضات، ولا تحذفها سياسة احتفاظ التشخيص الحالية.

## التحقق

```powershell
dotnet build HiringPs.sln -c Release
dotnet run --project tests/HiringPs.Checks -c Release -- --tools-check
dotnet run --project tests/HiringPs.Checks -c Release -- --pdf-check
dotnet run --project tests/HiringPs.Checks -c Release -- --workflow-check
```

فحص الأدوات يحتاج الأدوات الفعلية وara+eng ومتصفح Playwright، أو مسار متصفح مضبوطًا بـ`Browser__ExecutablePath`. لا يجري اختبار AI مدفوعًا ولا يحتاج SQL. فحوص SQL الجديدة ضمن `--workflow-sql-check` وتحتاج `HIRING_TEST_SQL` لقاعدة مؤقتة منفصلة؛ تشمل منع التكرار وحفظ النتائج وعدم إعادة اختبار AI المتوقف واستقلال قفل الأدوات عن الجمع.

اختبارات SQL وربط الصفحة به واختبار Windows/IIS وحساب الخدمة تحتاج بيئة اختبار متاحة؛ لا يُعد نجاح الفحوص المحلية إثباتًا لها. اختبار المزود الفعلي متروك للزر الصريح، ولم نرسل طلب AI فعليًا أثناء تطوير الميزة.


### نتيجة التحقق في هذه البيئة

التحقق الأولي لصفحة الأدوات شمل 29 فحصًا للأدوات وفحوص PDF والمعالجة. تغيّرت سياسة PDF لاحقًا إلى حذف الملفات المؤقتة؛ نتائج السياسة الحالية في دليل PDF. نجح توليد SQL المهاجرة وفحص عدم وجود تغييرات نموذج غير مرحّلة، وتحليل ملفات الترجمة وتطابق مفاتيح اللغتين. فحص Chromium استخدم المتصفح المحلي المثبت عبر `Browser__ExecutablePath`؛ تنزيل متصفح Playwright من CDN أعاد 403 في البيئة، لذلك لا ندعي نجاح تنزيل الحزمة هنا. فحوص SQL وواجهة الإدارة المتصلة بقاعدة البيانات لم تُشغّل لعدم توفر `HIRING_TEST_SQL`. اختبارات AI الفعلية لم تُرسل للمزود أثناء التطوير.
