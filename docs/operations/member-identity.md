# أسماء المستخدمين والبريد في الإدارة

- تعرض الاشتراكات والتنبيهات ورابط العضو في تفاصيل الدفع الاسم بدل معرّف Identity.
- نموذج منح الاشتراك يطلب البريد والباقة والمدة الاختيارية والسبب، ثم يفتح صفحة
  تأكيد تعرض الاسم والبريد والباقة. لا ينفذ المنح عند المعاينة.
- عند التأكيد يعيد النظام حل البريد؛ إذا اختفى أو صار يشير إلى حساب آخر فلا ينفذ
  المنح. لا يختار النظام حسابًا عشوائيًا عند تكرار البريد المطبع.
- البريد مطابق تمامًا بعد تطبيع Identity وحذف الفراغات المحيطة؛ البحث الجزئي لا
  يستخدم لمنح الاشتراك. الحساب يجب أن يملك ملف عضو.
- فلتر التنبيهات يطلب البريد ويعرض اسم الحساب المطابق. البحث العام في الاشتراكات
  والمدفوعات وسجل العمليات يدعم الاسم والبريد.
- نصوص تدقيق العضوية تعرض الاسم الحالي بدل مرجع `Member <id>` باستعلام أسماء
  واحد لكل صفحة. النص التاريخي المخزن يظل كما هو، ولا تتغير أرقام المعاملات.
- تبقى المعرفات داخل القاعدة والروابط والحقول المخفية وحدود الصلاحيات، ولا تطلب
  الواجهة من المسؤول كتابتها. بيانات التشخيص التقنية داخل ELMAH لا يعاد كتابتها.
- هذه تعديلات عرض وقراءة وتأكيد، ولا تحتاج إلى ماجريشن أو تعديل حسابات المستخدمين.

التحقق المحلي:

```sh
dotnet run --project tests/HiringPs.Checks -- --member-identity-check
```

يستخدم قاعدة SQLite مؤقتة للتأكد من مطابقة الحساب والتأكيد ورفض البريد المفقود
أو المكرر وتغير الحساب قبل المنح. لا ينشئ اشتراكات حقيقية. فحص SQL الإنتاجي
الكامل يبقى ضمن `--membership-sql-check` عند توفر SQL Server تجريبي.

بعد تشغيل `--membership-preview` يمكن تشغيل `scripts/check-member-identity-ui.cjs`
لفحص القوالب الفعلية بالعربية والإنجليزية على الهاتف وسطح المكتب.
