# المجالات وتخصيص تنبيهات الفرص

- المستخدم دون اشتراك سارٍ: 3 مجالات كحد أقصى. الحد يطبق في خدمة الحفظ، سواء جاء
  الطلب من المحرر أو زر إضافة البحث أو طلب HTTP معدل. الاشتراكات الملغاة والمستقبلية
  والمنتهية لا تمنح حد الباقة.
- صاحب الاشتراك: حد نسخة الباقة المشتراة. عند تعدد الاشتراكات السارية يؤخذ أكبر حد،
  وتبقى الباقة غير المحدودة غير محدودة في عدد المجالات فقط.
- لا تنبيهات فرص مع قائمة مجالات فارغة، حتى للباقة غير المحدودة. العضو دون اشتراك
  لا يكتسب استحقاق التنبيهات بمجرد تحديد المجالات. يراجع العامل الاشتراك والتفضيلات
  عند بناء الرسائل وعند الإرسال، فيلغي الرسائل التي فقدت المطابقة أو الاستحقاق.
- اختيارات قديمة تتجاوز الحد لا تُحذف تلقائيًا. يظل الحذف ومسح الاختيارات متاحين؛
  يجب تقليلها للحد المسموح قبل الحفظ. تذكيرات الاشتراك والفرص المحفوظة تبقى منفصلة
  عن تنبيهات الفرص الجديدة؛ تذكير فرصة محفوظة هو اختيار صريح لها وله إعداد مستقل.
- محرر الفرصة يعرض المجالات الموجودة ويقترح المطابق ثم البادئ بالنص ثم المحتوي ثم
  القريب إملائيًا. لا يستبدل اقتراح تقريبي اختيار المستخدم تلقائيًا. يمكن اختيار النص
  الجديد صراحة؛ الاسم الجديد لا يتجاوز 200 حرف. عند الحفظ يُعاد استخدام الاسم
  الموجود إذا تطابق بعد توحيد المسافات وحالة الأحرف وأشكال الألف فقط.
- محرر التفضيلات يدعم تصفية المجالات وإضافة اسم جديد لحساب المستخدم ضمن الحد نفسه؛
  إضافته للتفضيلات لا تنشر فرصة أو تضيف تسمية لكتالوج عام. تصبح التسميات الموجودة
  على الفرص المنشورة أو المؤرشفة متاحة في كتالوج تفضيلات الجميع.

لا يحتاج هذا التعديل ماجريشن. اختبارات SQL الاختيارية تتضمن رفض حفظ أكثر من ثلاثة
مجالات عبر الخدمة مباشرة دون تغيير البيانات السابقة؛ تشغيلها يحتاج قاعدة الاختبار
المؤقتة. اختبارات الواجهة تستخدم بيانات تجريبية ولا تنشر أو ترسل تنبيهات فعلية.
