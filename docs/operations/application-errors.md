# أخطاء التطبيق في قاعدة البيانات

يسجل الويب والعامل رسائل Error وCritical والاستثناءات المسجلة بمستوى Warning في
`dbo.ApplicationErrors`. ويسجل الويب ردود HTTP ذات الحالة 400 فأعلى أيضًا، بما فيها
الأخطاء التي لا يصاحبها استثناء. قد يكون للطلب سجل استثناء وسجل حالة HTTP بنفس رقم
المتابعة؛ الأول يشرح السبب والثاني يوضح نتيجة الطلب.

شغّل الماجريشنز أولًا ثم أعد تشغيل الويب والعامل بالنسخة الجديدة. جدول الأخطاء
ومؤشراه إضافيان، ولا يغيران بيانات المستخدمين أو مفاتيح الحماية. لا توجد بيانات
أخطاء تاريخية بأثر رجعي. لا ينشئ المسجل الجدول بنفسه ولا يحتاج صلاحية إنشاء جداول
أثناء التشغيل، بل INSERT فقط بعد تطبيق الماجريشن بواسطة حساب النشر.

في الموقع: افتح «النظام وAI» ثم «أخطاء النظام» تحت «سجل العمليات».
الصفحة متاحة لدور Admin فقط، وتدعم البحث برقم المتابعة أو الرسالة أو المسار،
والتصفية بالتطبيق والمستوى وأيام فلسطين والترقيم. تُحمّل تفاصيل الاستثناء عند فتح
سجل محدد فقط. إذا كان تسجيل الدخول نفسه معطلًا، استخدم الاستعلامات التالية من
قاعدة البيانات.

ابحث برقم المتابعة الظاهر على شاشة الخطأ:

```sql
DECLARE @TraceId nvarchar(200) = N'ضع رقم المتابعة هنا';
SELECT Id,
       [At] AT TIME ZONE 'West Bank Standard Time' AS [وقت فلسطين],
       Application, Level, Category, TraceId, Path, ExceptionType, Message, Details
FROM dbo.ApplicationErrors
WHERE TraceId = @TraceId
ORDER BY [At] DESC, Id DESC;
```

ولرؤية آخر الأخطاء:

```sql
SELECT TOP (100) Id,
       [At] AT TIME ZONE 'West Bank Standard Time' AS [وقت فلسطين],
       Application, Level, Category, TraceId, Path, ExceptionType, Message, Details
FROM dbo.ApplicationErrors
ORDER BY [At] DESC, Id DESC;
```

التخزين UTC، والاستعلام يعرض توقيت فلسطين. لا تُجمع أجسام الطلبات أو رؤوس الاعتماد
أو الكوكيز أو معاملات رابط الطلب. تُحجب أسرار الإعدادات المعروفة وأنماط كلمات المرور
والتوكنات في النصوص. رغم ذلك، لا تسجل معلومات شخصية أو أسرارًا حرة داخل رسائل
الأخطاء؛ لا يمكن لمنقح نصوص التعرف على كل معلومة حساسة غير معروفة مسبقًا. تفاصيل
الاستثناء مخصصة لمسؤول التشغيل، ولا تُعرض للزائر.

الحفظ غير متزامن في طابور محدود بـ2048 سجلًا، وباتصال مستقل عن معاملات العمل.
فشل الحفظ لا يعطل الطلب ولا يولد حلقة تسجيل ذاتية. عند انقطاع القاعدة أو امتلاء
الطابور تظهر ملاحظة في stderr وتبقى مقدّمات سجلات التشغيل الأصلية فعالة. لا يمكن
ضمان الحفظ داخل قاعدة معطلة، ولا حفظ أخطاء تسبق إنشاء المسجل أو الانهيار القسري
للعملية. الأخطاء التي يمسكها الكود دون تسجيلها، وأخطاء متصفح المستخدم، لا يلتقطها
ILogger تلقائيًا. لا يوجد حذف تلقائي لسجلات الأخطاء؛ راقب حجم الجدول وحدد مدة الاحتفاظ
المناسبة قبل حذفه دوريًا وفق سياسة التشغيل.
