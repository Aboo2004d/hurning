# أخطاء النظام — ELMAH

التسجيل الآن عبر `ElmahCore` و`ElmahCore.Sql` بالإصدار 2.1.2، دون مسجل SQL مخصص،
ودون أي `ILoggerProvider` للأخطاء. سجلات Console الاعتيادية للتطبيق تبقى كما هي.

## التشغيل

1. أوقف الويب والعامل القديمين أثناء نشر الاستبدال.
2. طبّق ماجريشن `20261022063250_ReplaceApplicationErrorsWithElmah`؛ يبدأ الويب
   بتطبيق الماجريشنز قبل تهيئة middleware الخاص بـELMAH.
3. شغّل النسخة الجديدة. يستخدم ELMAH اتصال `ConnectionStrings:Hiring` نفسه.
4. من حساب مسؤول: **النظام وAI ← أخطاء النظام** يحول إلى `/elmah/`.

الماجريشن ينشئ الجدول الأصلي `dbo.ELMAH_Error` ثم يحذف `dbo.ApplicationErrors`
وبياناته عمدًا؛ لا ترحيل للسجلات القديمة. لا تحتاج إلى جداول أو stored procedures
يدوية. يتحقق موفر ELMAH الأصلي من وجود جدوله عند تهيئته؛ الماجريشن ينشئه مسبقًا.
يبقى سجل العمليات مستقلًا ولا يُحذف. الماجريشنز التاريخية تبقى للحفاظ على تسلسل EF؛
إنشاء قاعدة جديدة ينتهي بجدول ELMAH فقط دون جدول الأخطاء القديم.

## ما يتم التقاطه

- استثناءات الويب غير المعالجة التي تمر عبر middleware الخاص بـELMAH.
- واجهة ELMAH الأصلية وتفاصيلها ومواردها وواجهات API والتصدير محمية للمسؤول فقط.
- لم يعد هناك تحويل لسجلات ILogger إلى القاعدة، ولا طابور تسجيل أخطاء مخصص.
- لا تُسجل أخطاء العامل أو الاستثناءات المعالجة داخليًا تلقائيًا في ELMAH؛ هذا مقصود
  حسب طلب الاعتماد على ELMAH مباشرة دون جسر logger. راجع Console لتلك الأخطاء.
- فشل تشغيل التطبيق قبل تركيب middleware أو فشل قاعدة تسجيل الأخطاء نفسها لا
  يمكن ضمان حفظه في ELMAH؛ راجع سجلات الاستضافة عند الحاجة.

## البيانات والحماية

يلتقط ELMAH رسالة الاستثناء وسلسلته الداخلية ومواضع الكود كاملة دون حد قص للرسالة
أو التفاصيل. يحتفظ باسم المستخدم ومعرفه وبريده وأدواره وحالة دخوله، وتظهر في صفحة
تفاصيل الخطأ الأصلية وفي Server Variables. للمستخدم الزائر لا توجد هوية مسجلة.

بحسب الإعداد المعتمد تُحجب كلمات المرور فقط، سواء في حقول النماذج أو الاستعلامات
أو قيم الإعدادات أو رسائل الاستثناء. بقية بيانات ELMAH الأصلية تبقى، بما فيها
الكوكيز والهيدرز وحقول النماذج؛ لذلك واجهة ELMAH والتصدير للمسؤول فقط. التقاط
الجسم الخام للطلب معطل؛ هذا لا يلغي حقول النموذج التي يجمعها ELMAH أصلًا.
يحتفظ السجل بـ`TraceId` و`Path` للمقارنة برقم المتابعة الظاهر للمستخدم.
الأسماء الطويلة التي تتجاوز سعة أعمدة ELMAH المفهرسة تبقى كاملة في Server Variables.

التخزين UTC في `TimeUtc`، ويحتوي قسم Server Variables على `PalestineTime`
محسوب عبر `TextRules.PalestineTimeZone`. واجهة الحزمة الأصلية تعرض أوقاتها وفق
سلوكها الأصلي والمتصفح، دون قالب أخطاء مخصص.

واجهة ELMAH وحدها تسمح بالأنماط المضمنة اللازمة لـBootstrap/Vue، وتسمح ببرنامج
تهيئة الحزمة المضمن عبر CSP hash محدد؛ بقية الموقع يحتفظ بسياسة CSP الحالية.
لا تفعل صفحة debug العامة الخاصة بـELMAH.

## استعلام تشخيصي

```sql
SELECT TOP (50) ErrorId, Application, TimeUtc, Type, Source, Message, AllXml
FROM dbo.ELMAH_Error
ORDER BY TimeUtc DESC, Sequence DESC;
```

`AllXml` يحتوي تفاصيل ELMAH المنظفة، ومنها رقم المتابعة. اسم التطبيق `HiringPs`.

## التحقق

```sh
dotnet run --project tests/HiringPs.Checks -- --error-log-check
```

يستخدم الفحص مخزن ELMAH الأصلي في الذاكرة لاختبار التقاط الاستثناءات وواجهة الحزمة
والتنقية والصلاحيات، دون كتابة أخطاء في قاعدة فعلية. يتضمن اختبار متصفح إذا توفر
Chromium في `/usr/bin/chromium`.
